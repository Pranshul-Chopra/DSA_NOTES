Lecture 1: Course Overview & Basic Structure of Computers

Understanding Computer Organization from Ground Level

🎯 What is Computer Organization and Architecture?

Computer Organization deals with how the various components of a computer system are interconnected and interact to execute programs efficiently.

Computer Architecture refers to the design principles and structure of computer systems at a higher level of abstraction.

Key Insight: Think of it like building a house: Computer Architecture is like the blueprint and design plan (how many rooms, where to place them), while Computer Organization is about the actual construction details (which materials, how to connect wiring and plumbing).

📊 Basic Structure of a Computer System

🔄 How Computer Systems Work

Real-World Scenario: Video Playback

When you play a video on your laptop:

  • Input Unit: Hard disk reads video file data
  • Memory Unit: Stores video frames in RAM for quick access
  • Processor: Decodes video data, handles playback controls
  • Output Unit: Display monitor shows video, speakers play audio

All these happen simultaneously and in coordination through the system bus!

📌 Summary - Lecture 1

A computer system is an integrated collection of functional units (Input, Memory, Output, Processor) that work together to process, store, and output data. Understanding these basic components is essential for grasping how instructions are executed and how different components communicate through buses.

Lecture 3: Basic Operational Concepts

Steps to Execute a Machine Instruction

🚀 The Fetch-Execute Cycle

Every instruction execution follows a basic cycle with specific steps involving register transfers and operations.

The Fetch-Execute Cycle:
  1. Fetch: Get instruction from memory
  2. Decode: Determine what the instruction means
  3. Execute: Perform the operation
  4. Store: Save results (if needed)

📝 Example: Add Instruction Execution

Instruction: ADD LOCA, R0

This instruction adds the content of memory location LOCA to register R0

Step-by-Step Execution:

  1. Load Program Counter:
    • PC ← Address of instruction (INSTR)
  2. Fetch Instruction:
    • IR ← [Memory location at PC]
  3. Increment PC:
    • PC ← PC + 1 (prepare for next instruction)
  4. Decode:
    • Identify operation (ADD) and operands
  5. Load Operand from Memory:
    • MAR ← LOCA (set memory address)
    • MBR ← [Memory location LOCA] (fetch data)
  6. Execute Addition:
    • R0 ← R0 + MBR (ALU performs addition)

💾 Key Registers Used in Execution

Register Full Name Purpose
PC Program Counter Holds address of next instruction to fetch
IR Instruction Register Holds the current instruction being executed
MAR Memory Address Register Holds the address of memory to be accessed
MBR Memory Buffer Register Holds data from or to be written to memory
R0, R1,... General Purpose Registers Store temporary data during execution

🔄 Three Address Instruction Example

Instruction: ADD R1, R2, R3

This adds R1 and R2, stores result in R3

Execution:

  1. Fetch instruction from memory
  2. Decode: Identify it's an ADD with 3 register operands
  3. ALU reads R1 and R2 values
  4. ALU performs R1 + R2
  5. Write result to R3
  6. PC increments to next instruction

🎯 Two Address Instruction Example

Instruction: ADD R1, R2

This adds R1 and R2, stores result back in R1

Execution:

  1. Fetch instruction from memory
  2. Decode: Identify it's an ADD with 2 register operands
  3. ALU reads R1 and R2
  4. ALU performs R1 + R2
  5. Write result to R1 (overwriting original value)

📌 Summary - Lecture 3

The Fetch-Execute cycle is the fundamental operational concept. Understanding how registers (PC, IR, MAR, MBR) work together to fetch, decode, and execute instructions is critical. Different instruction formats (1, 2, 3 addresses) have different execution paths.

↓ Compiler

⚙️ Bus Protocols

Buses operate according to specific protocols (rules) that govern how data transfer happens:

Synchronous Bus: All components use a common clock signal. Transfers happen at fixed time intervals. Simple but requires tight timing synchronization.
Asynchronous Bus: Components use handshaking signals (ready, acknowledge). More flexible but complex control logic. Used when components have different speeds.

📌 Summary - Lecture 4

A single bus connects all components and is controlled by specific protocols. System software acts as an intermediary between applications and hardware, translating high-level code through multiple layers to machine instructions that the CPU can execute.

Lecture 5: Performance Metrics & Factors

Measuring and Optimizing Computer Performance

📊 Fundamental Performance Equation

Execution Time = Instruction Count × CPI × Clock Cycle Time

T = IC × CPI × C

Where:

  • IC (Instruction Count): Total number of instructions executed
  • CPI (Cycles Per Instruction): Average clock cycles per instruction
  • C (Clock Cycle Time): Time for one clock cycle = 1/Clock Frequency

🎯 Example: Calculating Execution Time

Scenario: Running a Program
  • Total Instructions = 50,000,000
  • Average CPI = 2.7
  • Clock Rate = 2.0 GHz (C = 0.5 × 10⁻⁹ seconds)

Execution Time Calculation:

T = 50,000,000 × 2.7 × 0.5 × 10⁻⁹

T = 0.0675 seconds = 67.5 milliseconds

🔍 Three Main Factors Affecting Performance

Factor Component Influenced By Example Impact
Instruction Count (IC) Determined by algorithm Program, Compiler, ISA Better algorithm = fewer instructions
CPI Instruction execution complexity CPU design, ISA, Compiler Pipelining can reduce CPI
Clock Cycle Time (C) Hardware implementation Technology (nm), CPU design 5nm tech → faster cycles than 7nm

⚖️ The RISC vs CISC Tradeoff

RISC Architecture

  • Reduced Instruction Set
  • Simple instructions
  • More instructions needed (↑IC)
  • Lower CPI (↓CPI)
  • Faster clock (↓C)
  • Examples: ARM, MIPS

CISC Architecture

  • Complex Instruction Set
  • Complex instructions
  • Fewer instructions needed (↓IC)
  • Higher CPI (↑CPI)
  • Slower clock (↑C)
  • Examples: x86, x64
Key Finding: Experiments show RISC architecture generally gives better performance because the reduction in CPI and improvement in clock rate more than offset the increase in instruction count.

📈 Speedup and Performance Comparison

Performance Metric:

Performance = 1 / Execution Time

Speedup = Time_old / Time_new = Performance_new / Performance_old

Comparing Two Machines:
  • Machine A: Execution Time = 10 seconds
  • Machine B: Execution Time = 25 seconds

Speedup of A over B:

Speedup = 25 / 10 = 2.5

Meaning: Machine A is 2.5 times faster than Machine B

🎲 Scenario: Optimizing Performance

Real Situation: Video Rendering Software

Current Performance (Original Compiler):

  • IC = 50,000,000 instructions
  • CPI = 2.7
  • Clock Rate = 2.0 GHz (C = 0.5 × 10⁻⁹)
  • Execution Time = 0.0675 seconds

After Optimization (New Compiler + Faster CPU):

  • IC = 40,000,000 instructions (20% reduction through better compiler)
  • CPI = 3.0 (slightly worse due to more complex instructions)
  • Clock Rate = 2.4 GHz (C = 0.4167 × 10⁻⁹)
  • Execution Time = 40,000,000 × 3.0 × 0.4167 × 10⁻⁹ = 0.050 seconds

Overall Speedup:

Speedup = 0.0675 / 0.050 = 1.35 (35% faster!)

Analysis: Even though CPI increased, the reduction in IC and improvement in clock rate resulted in 35% overall performance gain.

📌 Summary - Lecture 5

Computer performance is determined by three factors: Instruction Count, CPI, and Clock Cycle Time. These factors often have tradeoffs. Understanding these metrics helps in making design decisions. RISC vs CISC represents different performance optimization strategies, with RISC generally winning overall.

Lecture 7: Addition & Subtraction of Signed Numbers

Arithmetic Operations at Hardware Level

➕ 2's Complement Addition

Example 1: Adding Two Positive Numbers

+5 + +3:

    0101  (+5)
  + 0011  (+3)
  ------
    1000  (+8) ✓
Example 2: Adding Positive and Negative

+5 + (-3):

    0101  (+5)
  + 1101  (-3 in 2's complement)
  ------
   10010  
   (discard carry) = 0010 (+2) ✓

➖ 2's Complement Subtraction

Rule: A - B = A + (-B) (convert subtraction to addition)

Example: 5 - 3 = 5 + (-3)

-3 in 2's complement = 1101

    0101  (+5)
  + 1101  (-3)
  ------
   10010  = 0010 (+2) ✓

⚠️ Overflow Detection

Overflow Occurs When:
  • Adding two positive numbers produces a negative result
  • Adding two negative numbers produces a positive result

Detection: If signs of operands are same but result sign is different → Overflow!

Overflow Example (4-bit):

+7 + +2:

    0111  (+7)
  + 0010  (+2)
  ------
    1001  (-7) ← WRONG! This is overflow!

Range is -8 to +7, so +9 cannot be represented.

📌 Summary - Lecture 7

Addition and subtraction in 2's complement is straightforward and can use the same hardware (ALU). Overflow must be detected to ensure correct results. The sign bit behavior is automatic in 2's complement arithmetic.

Lecture 8: Memory Locations & Addressing

How Computers Access Data in Memory

🗂️ Memory Organization

Byte-Addressable Memory: Each byte (8 bits) has a unique address. A 32-bit address can access 2^32 = 4GB of memory.
MEMORY LAYOUT: Address Content 0x00000 [Byte 0] ← First byte at address 0 0x00001 [Byte 1] 0x00002 [Byte 2] 0x00003 [Byte 3] ... 0x7FFFFFFF [Byte n] ← Last byte (4GB system)

🔄 Big-Endian vs Little-Endian

Two ways to store multi-byte values in memory:

Big-Endian

  • Most Significant Byte first
  • Address 0x1000: MSB (0x12)
  • Address 0x1001: 0x34
  • Address 0x1002: 0x56
  • Address 0x1003: LSB (0x78)
  • Used in: PowerPC, SPARC

Little-Endian

  • Least Significant Byte first
  • Address 0x1000: LSB (0x78)
  • Address 0x1001: 0x56
  • Address 0x1002: 0x34
  • Address 0x1003: MSB (0x12)
  • Used in: x86, ARM
Storing Value 0x12345678: 
Big-Endian (Address 0x1000):    Little-Endian (Address 0x1000):
0x1000: 0x12                    0x1000: 0x78
0x1001: 0x34                    0x1001: 0x56
0x1002: 0x56                    0x1002: 0x34
0x1003: 0x78                    0x1003: 0x12

📍 Memory Word Alignment

Modern processors access memory more efficiently when data is aligned (address is multiple of data size).

Alignment Rules:
  • Byte (8-bit): No alignment required
  • Word (16-bit): Address must be multiple of 2
  • Double Word (32-bit): Address must be multiple of 4
  • Quad Word (64-bit): Address must be multiple of 8

💾 Scenario: Data Storage

Storing a Struct in Memory: 
struct Person {
    int age;        // 4 bytes
    char name[4];   // 4 bytes
    short id;       // 2 bytes
};  // Total: 10 bytes

Memory Layout (Little-Endian):
0x1000-0x1003: [age value]
0x1004-0x1007: [name chars]
0x1008-0x1009: [id value]

📌 Summary - Lecture 8

Memory is byte-addressable with unique addresses for each byte. Multi-byte values can be stored in two ways (Big-Endian or Little-Endian). Understanding memory organization is crucial for correct data access and storage efficiency.

📋 Instruction Types

Type Format Example How It Works
Load LOAD Ri, Address LOAD R1, [0x1000] Load data from memory into register

🎯 Assembly Language Notation

Assembly language provides mnemonics (easy-to-remember names) for machine instructions.

Simple Program: Add A + B, Store in C 
; High-level: C = A + B

    LOAD  R1, A    ; Load A into R1
    LOAD  R2, B    ; Load B into R2
    ADD   R3, R1, R2  ; R3 = R1 + R2
    STORE R3, C    ; Store result in C
    HALT           ; End program

↔️ Instruction Sequencing

Instructions execute sequentially unless:

  • A branch instruction redirects execution
  • A jump instruction changes Program Counter
With Branch: 
    LOAD  R1, X
    LOAD  R2, Y
    CMP   R1, R2      ; Compare R1 and R2
    BLE   LOOP        ; Branch if Less or Equal
    LOAD  R3, Z
    HALT
LOOP: ADD   R1, 1    ; This only executes if R1 <= R2
    JMP   LOOP        ; Jump back

📌 Summary - Lectures 9-10

Instructions follow specific formats with opcodes and operands. Assembly language provides a human-readable notation for machine instructions. Understanding instruction types (Load, Store, Arithmetic, Branch) is essential for programming at hardware level.

Lecture 11-13: Addressing Modes & Branching

How Instructions Access Operands

🎯 Different Addressing Modes

An addressing mode specifies how the operand address is determined from the instruction.

Mode Format Example Effective Address When Used
Immediate ADD R1, #5 R1 = R1 + 5 5 (from instruction) Constants
Direct LOAD R1, 0x1000 R1 = Memory[0x1000] 0x1000 Fixed locations
Register ADD R1, R2 R1 = R1 + R2 Value in R2 Register-to-register
Indirect LOAD R1, (R2) R1 = Memory[R2] Value in R2 is address Pointer dereferencing
Indexed LOAD R1, 0x1000(R2) R1 = Memory[0x1000+R2] 0x1000 + R2 Array access

🎲 Scenario: Array Access Using Indexed Addressing

Access Array Elements: 
int arr[5] = {10, 20, 30, 40, 50};  // Base at 0x1000

C Code:              Assembly (Indexed):
x = arr[2];          LOAD R1, 2     ; Load index 2
                     LOAD R2, 0x1000(R1)  ; Load arr[2]
                     STORE R2, x

; R1 = 2 (index)
; Effective Address = 0x1000 + (2 * 4 bytes) = 0x1008
; Memory[0x1008] = 30

🔀 Branching Instructions

Branching allows conditional execution and loops.

Instruction Condition Sets By
BRZ (Branch if Zero) Register value == 0 Zero flag
BRN (Branch if Negative) Register value < 0 Sign flag
BRV (Branch if Overflow) Overflow occurred Overflow flag
BRC (Branch if Carry) Carry occurred Carry flag
While Loop in Assembly: 
; while (i > 0) { i--; }

    LOAD  R1, 5      ; i = 5
LOOP: 
    SUB   R1, 1      ; i--
    BRN   EXIT       ; if i < 0, exit
    JMP   LOOP       ; go back
EXIT:
    HALT

📌 Summary - Lectures 11-13

Addressing modes determine how operands are specified in instructions. They range from simple (immediate, direct) to complex (indexed, indirect). Understanding branching with condition codes enables writing loops and conditional logic in assembly.

Lecture 14-19: Input/Output Organization

How Computers Communicate with Peripherals

🔌 I/O Module Architecture

I/O Module: Acts as intermediary between processor and external devices. Contains control logic, status registers, and data buffers.
I/O MODULE SCHEMATIC: ┌─────────────────────────────────┐ │ I/O MODULE │ │ ┌──────────────────────────┐ │ │ │ Control Logic │ │ │ └──────────────────────────┘ │ │ ┌──────────────────────────┐ │ │ │ Status Registers │ │ │ └──────────────────────────┘ │ │ ┌──────────────────────────┐ │ │ │ Data Buffer/Register │ │ │ └──────────────────────────┘ │ └─────────────────────────────────┘ │ │ ▼ ▼ CPU/Memory External Device (Printer, Disk, etc)

🗺️ Memory-Mapped vs I/O-Mapped Devices

Memory-Mapped I/O

  • Device registers appear as memory locations
  • Same instructions for memory and I/O
  • LOAD/STORE access devices
  • Reduces instruction count
  • Example: ARM, x86

I/O-Mapped I/O

  • Separate I/O address space
  • Special IN/OUT instructions
  • Clearer distinction
  • Limited address space for I/O
  • Example: x86 I/O ports

📤 Three Data Transfer Techniques

Technique CPU Role Speed Overhead Best For
Programmed I/O Actively polls device Slow Very High Slow devices, keyboard
Interrupt-Driven Waits for interrupt signal Medium Medium Medium-speed devices
Direct Memory Access DMA controller handles transfer Fast Low High-speed devices, disk

🔄 Programmed I/O

Reading 2048 bytes from device:
  • Bus width: 32 bits = 4 bytes
  • Number of transfers: 2048 / 4 = 512
  • Time per transfer: 4 μs
  • Total CPU time: 512 × 4 μs = 2,048 μs = 2.048 ms

CPU remains busy throughout - inefficient for slow operations!

⚡ Interrupt-Driven I/O

How Interrupts Work:
  1. Device signals need for attention (interrupt request)
  2. CPU finishes current instruction
  3. CPU saves program state (PC, registers)
  4. CPU jumps to Interrupt Service Routine (ISR)
  5. ISR handles the device
  6. CPU returns to original program
Device: 8 KB/s, Interrupt processing: 100 μs per byte
  • Interrupts per second: 8192
  • CPU time per byte: 100 + 8 = 108 μs
  • Total CPU usage: 8192 × 108 μs ≈ 88.5%

Still very high overhead! Many interrupts per second causes excessive context switching.

🚀 Direct Memory Access (DMA)

DMA Advantage: Device transfers data directly to memory without CPU involvement. CPU overhead is minimal (only for setup and completion interrupt).
DMA Transfer Scenario:
  • Hard disk: 4000 KB/s
  • Block size: 8 KB
  • Transfers per second: 500
  • Setup overhead: 2000 CPU cycles
  • Completion interrupt: 1000 CPU cycles
  • CPU total: 500 × (2000 + 1000) = 1.5M cycles/sec
  • On 50 MHz processor: 1.5M / 50M = 3% overhead

Dramatically better than programmed or interrupt-driven I/O!

🎛️ DMA Controller & Cycle Stealing

Cycle Stealing: DMA controller temporarily takes bus cycles from CPU.

DMA at 2400 bytes/s transferring 32-bit words (4 bytes):
  • Transfers per second: 2400 / 4 = 600
  • Cycles lost to DMA: 600 cycles/sec
  • CPU running at 1M instructions/sec
  • Slowdown: 600 / 1,000,000 = 0.06%

Minimal impact on CPU performance!

📌 Summary - Lectures 14-19

I/O is handled through three main techniques: Programmed I/O (CPU-intensive), Interrupt-driven (better but still overhead), and DMA (best performance). Memory-mapped vs I/O-mapped determines how the CPU accesses device registers. Understanding interrupt handling and DMA is crucial for efficient I/O operations.

Lecture 20-24: Cache Memory & Performance

Memory Hierarchy and Speed Optimization

📚 Memory Hierarchy

MEMORY HIERARCHY (Top = Fast + Small, Bottom = Slow + Large): ┌──────────────────────────┐ │ Registers (CPU) │ ~1 ns, ~1 KB, Fastest ├──────────────────────────┤ │ L1 Cache │ ~3 ns, ~32 KB ├──────────────────────────┤ │ L2 Cache │ ~10 ns, ~256 KB ├──────────────────────────┤ │ L3 Cache │ ~40 ns, ~8 MB ├──────────────────────────┤ │ Main Memory (RAM) │ ~100 ns, ~16 GB ├──────────────────────────┤ │ Secondary Storage │ ~10 ms, ~1 TB, Slowest │ (Disk, SSD) │ └──────────────────────────┘

🎯 Cache Basics

Cache Principle: Small, fast memory holds frequently accessed data from main memory. When CPU needs data, check cache first (cache hit), if not there, fetch from memory (cache miss).
Concept Definition Example
Cache Hit Data found in cache Access time: 3 ns
Cache Miss Data not in cache, fetch from memory Access time: 100 ns + 3 ns = 103 ns
Hit Rate % of accesses that hit cache 95% (very good)
Miss Rate % of accesses that miss cache 5% (100% - 95%)

⏱️ Effective Memory Access Time (EMAT)

EMAT = Hit Rate × Cache Access Time + Miss Rate × Memory Access Time

EMAT = H × Tc + (1-H) × Tm

Where: H = Hit Rate, Tc = Cache time, Tm = Memory time

Scenario: Cache System Performance
  • Cache access time: 20 ns
  • Memory access time: 200 ns
  • Hit rate: 95%

EMAT Calculation:

EMAT = 0.95 × 20 + 0.05 × 200

EMAT = 19 + 10 = 29 ns

Without cache: Always 200 ns

Speedup: 200 / 29 ≈ 6.9x faster!

🗂️ Three Mapping Techniques

1️⃣ Direct Mapping

Rule: Each memory block maps to exactly one cache line.

Cache Index = (Memory Address) mod (Number of Cache Lines)

Example:
  • Cache: 16 KB, block size: 256 bytes → 64 cache lines
  • Memory: 128 KB → 512 blocks
  • Memory block 0 → Cache line 0
  • Memory block 64 → Cache line 0 (conflict!)

Pro: Simple. Con: High conflict misses

2️⃣ Fully Associative Mapping

Rule: Any memory block can go into any cache line.

Pro: No conflicts. Con: Complex, need to search all lines

3️⃣ Set-Associative Mapping

Rule: Memory block maps to a set of cache lines (trade-off).

2-way: Each block can go into 2 lines

4-way: Each block can go into 4 lines

Pro: Good balance. Con: Moderate complexity

💾 Cache Formula Calculations

Cache Parameters:

Total bits in cache = (Tag bits + Valid bit + Data bits) × Number of lines

Number of cache lines = Cache Size / Block Size

Address bits = Tag bits + Index bits + Offset bits

Where: Offset bits = log₂(Block Size)

Calculate Cache Parameters:
  • Cache: 16 KB
  • Block size: 256 bytes
  • Main memory: 128 KB

Solution:

  • Cache lines = 16 KB / 256 B = 64 lines
  • Offset bits = log₂(256) = 8 bits
  • Index bits = log₂(64) = 6 bits
  • Address bits = log₂(128 KB) = 17 bits
  • Tag bits = 17 - 6 - 8 = 3 bits

🔄 Replacement Algorithms

Algorithm Idea Performance Complexity
LRU (Least Recently Used) Remove least recently accessed line Best High
FIFO (First In First Out) Remove oldest line Good Low
Random Remove random line Fair Minimal

📌 Summary - Lectures 20-24

Cache is a critical component for system performance. Understanding mapping techniques (direct, associative, set-associative), calculating EMAT, and replacement algorithms is essential. Cache design involves tradeoffs between speed, size, and miss rate.

Lecture 25-27: Fast Arithmetic Circuits

Hardware Implementation of Arithmetic Operations

🔧 Design of Fast Adders

Ripple Carry Adder: Each bit addition produces a carry that "ripples" to next position. Simple but slow.
4-bit Addition: 
    0110  (6)
  + 0101  (5)
  ------
    1011  (11)

Carry propagation:
Bit 0: Cin=0, 0+1 → Sum=1, Cout=0
Bit 1: Cin=0, 1+0 → Sum=1, Cout=0
Bit 2: Cin=0, 1+1 → Sum=0, Cout=1
Bit 3: Cin=1, 0+0 → Sum=1, Cout=0
Result: 1011 ✓
Carry Lookahead Adder: Predicts carries in advance, reducing delay. Used in modern processors.

✖️ Multiplication Circuits

Unsigned Multiplication

4-bit × 4-bit = 8-bit Product 
Multiply: 5 × 3 = 15

      0101  (5)
    × 0011  (3)
    ------
      0101  (5 × 1)
     0101   (5 × 1, shifted)
    0000    (5 × 0, shifted)
    0000    (5 × 0, shifted)
    ------
    01111   (15) ✓

Signed Multiplication (Booth's Algorithm)

Booth's Algorithm: Efficiently handles signed numbers by recognizing bit patterns and using subtraction. Reduces number of operations.

➗ Division Circuits

Integer Division: 15 ÷ 3 = 5 (remainder 0) 
Long Division Method:
      0101  (quotient)
    ------
  3 | 1111  (15)
      1010  (30)
      ----
      0101  (5)
      0011  (3)
      ----
      0010  (2)
      ----

Fast arithmetic circuits use carry lookahead for addition, shift-and-add for multiplication, and shift-and-subtract for division. Understanding these low-level implementations is important for computer organization.

Lecture 28: Control Unit Design Basics

Orchestrating Instruction Execution

🎛️ Control Unit Architecture

Control Unit: Interprets instructions and generates control signals to direct operations of other components. It's the "orchestrator" of instruction execution.

🔌 Two Design Approaches

Aspect Hardwired Control Microprogrammed Control
Design Combinational logic circuits Microinstruction sequences
Speed Very fast Slightly slower
Flexibility Fixed, hardware modifications needed High, can reprogram
Complexity Complex design, simple execution Simple design, complex logic
Used In High-performance CPUs, Reduced ISA Complex instruction sets, older systems

⚡ Hardwired Control Example

Generating Control Signals for ADD R1, R2, R3: 
Instruction: ADD R1, R2, R3

Control Signals Generated:
1. ALU_Operation ← ADD (3 bits)
2. R_Read ← R2, R3 (Select R2 and R3 for reading)
3. R_Write ← R1 (Select R1 for writing)
4. ALU_In1 ← R2_output
5. ALU_In2 ← R3_output
6. ALU_Enable ← 1 (Enable ALU)
7. Memory_Enable ← 0 (No memory access)
8. PC_Update ← 1 (Increment PC)

All generated based on opcode 000001 by combinational logic

📋 Microprogrammed Control

Microinstructions specify control signals for each micro-operation.

Type Description Advantages Disadvantages
Horizontal One bit per control signal (wide microinstructions) Fast execution Large memory needed for microcode
Vertical Encoded signals (narrow microinstructions) Space efficient Slower (need decoding)
Hybrid Combination of both Balanced performance/space More complex

🎯 Microprogram Example

Microprogram for LOAD R1, [Address]: 
Microinstruction 1 (Fetch):
  - MAR ← PC
  - Memory_Read ← 1
  - Next address ← MicroPC + 1

Microinstruction 2 (Decode):
  - IR ← MBR
  - PC ← PC + 1
  - Next address ← MicroPC + 1

Microinstruction 3 (Execute):
  - MAR ← Extract_Address(IR)
  - Memory_Read ← 1
  - Next address ← MicroPC + 1

Microinstruction 4 (Writeback):
  - R1 ← MBR
  - Next address ← Fetch_address

🔄 Basic Pipelining Concept

Pipelining Principle: Divide instruction execution into stages, allowing multiple instructions at different stages simultaneously.
SIMPLE 5-STAGE PIPELINE: Stage 1: Fetch (F) - Get instruction Stage 2: Decode (D) - Interpret instruction Stage 3: Execute (E) - Perform operation Stage 4: Memory (M) - Access memory if needed Stage 5: Writeback (W) - Store result Without Pipeline (Sequential): Cycle: 1 2 3 4 5 6 7 8 9 I1F-D-E-M-W I2F-D-E-M-W I3F-D-E-M-W Total: 15 cycles for 3 instructions With 5-Stage Pipeline: Cycle: 1 2 3 4 5 6 7 I1F I1D I1E I1M I1W I2F I2D I2E I2M I2W I3F I3D I3E I3M I3W Total: 7 cycles for 3 instructions Speedup: ~2.1x
Pipeline Hazards:
  • Structural Hazard: Two instructions need same resource (e.g., memory)
  • Data Hazard: Instruction depends on result of previous instruction
  • Control Hazard: Branch changes PC, pipeline flushes

📌 Summary - Lecture 28

Control unit can be implemented using hardwired (fast) or microprogrammed (flexible) approach. Understanding how instructions are orchestrated through stages and how pipelining improves throughput is crucial for advanced computer architecture knowledge.
