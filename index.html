Introduction to OOP

History · Evolution · Benefits · OOP vs Procedural

🎓 Professor's Note — Why OOP?

Imagine you're building a hospital management system. In procedural programming (C, Pascal), you'd write thousands of functions operating on global data — eventually it becomes impossible to manage. OOP solves this by organizing code around real-world entities: a Patient object has data (name, age) and behaviour (admit, discharge).

📖 Procedural vs OOP

ProceduralOOP
Functions + Data (separate)Objects (data + methods together)
Top-down designBottom-up design
Data exposed globallyData hidden (encapsulation)
Code reuse: difficultCode reuse: inheritance
Example: CExample: Java, C++, C#

🔑 4 Pillars of OOP

  • Encapsulation — wrapping data + methods; hiding internal state
  • Abstraction — showing only what's necessary (ATM interface)
  • Inheritance — child class reuses parent class (IS-A)
  • Polymorphism — one action, many forms (overloading/overriding)
💡 Exam Tip: OOP was born with Simula (1960s), popularized by Smalltalk, then C++ (Bjarne Stroustrup) and Java (James Gosling, 1995). Java is platform-independent — "Write Once, Run Anywhere" via the JVM (bytecode).

public class OperatorsDemo {

        int i = 5;

    }
}

Control Flow

if-else · switch · for · while · do-while · break · continue

🔀 Decision Statements

  • if — single condition
  • if-else — two paths
  • if-else-if ladder — multiple independent conditions checked in order
  • nested if — if inside if
  • switch — multi-way branch based on value (int, char, String)

🔁 Loops

  • for — when count is known
  • while — condition checked before; may not execute at all
  • do-while — condition checked after; executes at least once
  • break — exits loop immediately
  • continue — skips current iteration, goes to next
JavaSwitch + Loops Demo
public class ControlFlow {
    public static void main(String[] args) {
        // switch-case
        int day = 3;
        switch (day) {
            case 1: System.out.println("Monday"); break;
            case 3: System.out.println("Wednesday"); break; // ← executes this
            default: System.out.println("Other day");
        }

        // for loop with continue
        for (int i = 1; i <= 5; i++) {
            if (i == 3) continue; // skip 3
            System.out.print(i + " "); // prints: 1 2 4 5
        }

        // do-while — always runs at least once
        int x = 10;
        do {
            System.out.println("Runs once even if false! x=" + x);
            x++;
        } while (x < 5); // false immediately, but body ran once
    }
}

Type Casting (Type Conversion)

Widening · Narrowing · Implicit · Explicit

📈 Widening (Implicit / Automatic)

Smaller type → larger type. Done automatically by Java. No data loss.

Order: byte → short → int → long → float → double

📉 Narrowing (Explicit)

Larger type → smaller type. Must be manually cast. May cause data loss.

Syntax: (targetType) value

JavaType Casting Demo
public class TypeCasting {
    public static void main(String[] args) {
        // Widening — automatic
        int i = 100;
        double d = i;   // int → double, no cast needed
        System.out.println("Widening: " + d);  // 100.0

        // Narrowing — explicit cast required
        double pi = 3.14159;
        int approx = (int) pi;  // decimal part LOST
        System.out.println("Narrowing: " + approx); // 3

        // char to int (Unicode value)
        char c = 'A';
        int ascii = c;
        System.out.println("char 'A' as int: " + ascii); // 65
    }
}
⚠️ Remember: Narrowing can silently lose data. double → int truncates (doesn't round). Cast explicitly or you get a compile error.

Wrapper Classes

Autoboxing · Unboxing · Utility Methods

📦 What & Why

Java collections (ArrayList, HashMap) can only store objects, not primitives. Wrapper classes bridge this gap — each primitive has a corresponding class in java.lang.

PrimitiveWrapper ClassKey Method
intIntegerInteger.parseInt("42")
doubleDoubleDouble.parseDouble("3.14")
charCharacterCharacter.isDigit('5')
booleanBooleanBoolean.parseBoolean("true")
byteByteByte.parseByte("127")
JavaAutoboxing & Unboxing
import java.util.ArrayList;
public class WrapperDemo {
    public static void main(String[] args) {
        // AUTOBOXING: primitive → object (automatic)
        int num = 357;
        Integer obj = num;   // Java auto-wraps

        // UNBOXING: object → primitive (automatic)
        Integer intObj = 99;
        int val = intObj;    // Java auto-unwraps

        // Collections require objects — autoboxing handles it
        ArrayList<Integer> list = new ArrayList<>();
        list.add(25);       // int 25 → autoboxed to Integer
        int x = list.get(0); // Integer → unboxed to int
        System.out.println(x); // 25

        // Utility: String → int
        int parsed = Integer.parseInt("42");
        System.out.println("Parsed: " + parsed); // 42
    }
}

Strings & Arrays

String Pool · Immutability · StringBuilder · 1D/2D Arrays

🔤 Strings

  • String objects are immutable in Java
  • Created via literal → stored in String Constant Pool
  • Created via new → stored in heap (not pool)
  • StringBuilder: mutable, faster (single thread)
  • StringBuffer: mutable, thread-safe (synchronized)

📋 Arrays

  • Fixed-size collection of same type
  • Zero-indexed: arr[0] to arr[n-1]
  • Default values: int[] → 0, boolean[] → false, Object[] → null
  • arr.length gives size (not a method!)
JavaStrings & Arrays
public class StringArrayDemo {
    public static void main(String[] args) {
        // String immutability — original unchanged!
        String s = "Sachin";
        s.concat(" Tendulkar");      // new object created, s unchanged
        System.out.println(s);          // Sachin

        // Mutable: StringBuilder
        StringBuilder sb = new StringBuilder("Hello");
        sb.append(" World");
        System.out.println(sb);         // Hello World (modified)

        // String pool demo
        String s1 = "Java";
        String s2 = "Java";            // same pool object
        System.out.println(s1 == s2);   // true (same reference)

        // Arrays: 1D
        int[] marks = {90, 85, 78, 92};
        for (int m : marks) System.out.print(m + " ");

        // Arrays: 2D (matrix)
        int[][] matrix = {{1,2},{3,4},{5,6}};
        System.out.println("\n" + matrix[1][0]);  // 3
    }
}
💡 Key: == on Strings compares references. Use .equals() to compare content! And str.length() is a method for Strings, but arr.length is a field for arrays (no parentheses).

A Car class is a blueprint. Every actual car on the road (Swift, i20, Nexon) is an object — an instance created from that blueprint. The blueprint defines what a car has (engine, color) and what it does (drive, brake). Objects have their own state but share the same blueprint.

  • Methods — behavior of the object
  • Constructors — initializers called on creation
  • Blocks — initialization blocks
  • Nested Classes — class inside class

🔵 Object Characteristics

  • State — value of instance variables
  • Behaviour — methods (deposit, withdraw)
  • Identity — unique ID given by JVM internally

Created with: ClassName obj = new ClassName();

class Student {

    int rollNo;
    String name;
    float cgpa;

    // Method (behaviour)

static Keyword

Part of L10: Class Fundamentals · Static Variable · Static Method · Static Block

📌 What static Means

  • Belongs to the class, not to any object
  • Memory allocated once at class loading time
  • Accessed as: ClassName.member
  • Static method cannot access instance (non-static) members directly

⚡ Static Block

Runs once when the class is loaded — before any object is created. Used to initialize static variables that need complex logic.

Javastatic Variable, Method, Block
class Student {
    int id;
    String name;
    static String college = "MUJ";   // shared across ALL Student objects
    static int count = 0;             // counts total students created

    // Static block — runs once on class load
    static {
        System.out.println("Student class loaded. College: " + college);
    }

    Student(int i, String n) {
        id = i; name = n;
        count++;  // increment shared counter
    }

    static void showCount() {  // static method
        System.out.println("Total students: " + count);
        // System.out.println(id); // ERROR — can't access instance var!
    }
}

public class Main {
    public static void main(String[] args) {
        new Student(1, "Aarav");
        new Student(2, "Bina");
        new Student(3, "Chirag");
        Student.showCount();  // Total students: 3
    }
}

L13

Constructors

Default · Parameterized · Copy · Constructor Chaining · Singleton

🏗️ Rules of Constructors

  • Same name as the class
  • No return type (not even void)
  • Called automatically when object is created via new
  • Cannot be static, abstract, or final
  • Constructors are NOT inherited
  • If you don't write any, compiler provides a default constructor

🔢 Types

  • Default — no arguments; compiler-provided if none written
  • Parameterized — accepts arguments to initialize state
  • Copy — takes same class object, copies values (deep copy)

⛓️ Constructor Chaining

Calling one constructor from another in the same class using this().

Must be the first statement in the constructor body.

JavaAll Constructor Types
class Book {
    String title;
    double price;

    // 1. Default Constructor
    Book() {
        title = "Unknown";
        price = 0.0;
        System.out.println("Default constructor called");
    }

    // 2. Parameterized Constructor
    Book(String t, double p) {
        title = t;
        price = p;
    }

    // 3. Copy Constructor
    Book(Book other) {
        this.title = other.title;
        this.price = other.price;
    }

    // 4. Constructor Chaining with this()
    Book(String t) {
        this(t, 99.0);  // calls parameterized constructor
    }
}

public class Main {
    public static void main(String[] args) {
        Book b1 = new Book();                    // default
        Book b2 = new Book("Java Complete", 550); // parameterized
        Book b3 = new Book(b2);                  // copy
        Book b4 = new Book("OOP Basics");        // chained → price=99.0
        System.out.println(b3.title);              // Java Complete
        System.out.println(b4.price);              // 99.0
    }
}

🔒 Singleton Class — Private Constructor

A Singleton allows at most ONE object of a class. The constructor is private so no outside code can call new. A public static method returns the single instance. Classic use case: Database Connection Pool, Logger.

JavaSingleton Pattern
class DBConnection {
    private static DBConnection instance;  // single instance

    private DBConnection() {               // private constructor
        System.out.println("DB connected!");
    }

    public static DBConnection getInstance() {
        if (instance == null) instance = new DBConnection();
        return instance;
    }
}
// DBConnection d = new DBConnection(); // ERROR — private!
// DBConnection d = DBConnection.getInstance(); // OK

this Keyword

Part of L13: Constructors · Current Object Reference · 6 Uses

🔵 6 Uses of this

  • this.field — refers to current class instance variable (disambiguates from local)
  • this.method() — invokes current class method (implicit, rarely needed)
  • this() — invokes current class constructor (chaining)
  • this as argument — passes current object to a method
  • this in constructor arg — passes current object
  • return this — returns current class instance from a method
Javathis keyword — most important uses
class Student {
    int rollno;
    String name;
    float fee;

    // USE 1: this.field to resolve name collision
    Student(int rollno, String name, float fee) {
        this.rollno = rollno;   // this.rollno = instance var; rollno = param
        this.name   = name;
        this.fee    = fee;
    }

    // USE 3: this() for constructor chaining
    Student(int rollno, String name) {
        this(rollno, name, 5000f); // calls the 3-param constructor
    }

    // USE 6: return this (method chaining pattern)
    Student setName(String n) { this.name = n; return this; }
    Student setFee(float f)   { this.fee  = f; return this; }

    void display() {
        System.out.println(rollno + " " + name + " " + fee);
    }
}

public class Main {
    public static void main(String[] args) {
        Student s = new Student(101, "Ankit", 5000f);
        s.display(); // 101 Ankit 5000.0

        // Method chaining using return this
        new Student(102, "X").setName("Sumit").setFee(6000f).display();
    }
}

Method Overloading

Compile-Time Polymorphism · Static Binding · Early Binding

📖 Definition

Multiple methods with the same name but different parameter lists (number, type, or order) in the same class. Resolved at compile time — also called Static Binding / Early Binding / Compile-Time Polymorphism.

Return type alone does NOT differentiate overloaded methods.

✅ Valid Overloading — Different number of params

add(int a, int b)

add(int a, int b, int c)

✅ Valid Overloading — Different types

add(int a, int b)

add(double a, double b)

JavaMethod Overloading — Adder
class Adder {
    // Different number of params
    static int add(int a, int b)          { return a + b; }
    static int add(int a, int b, int c) { return a + b + c; }

    // Different data types
    static double add(double a, double b) { return a + b; }

    // Overloading with String
    static String add(String a, String b) { return a + b; }
}

public class TestOverloading {
    public static void main(String[] args) {
        System.out.println(Adder.add(11, 11));          // 22
        System.out.println(Adder.add(11, 11, 11));      // 33
        System.out.println(Adder.add(12.3, 12.6));     // 24.9
        System.out.println(Adder.add("Hello", " World")); // Hello World
    }
}
💡 Can we overload main()? YES! Java allows multiple main methods with different signatures. But the JVM always calls public static void main(String[] args) as the entry point.

Objects as Parameters & Argument Passing

Call by Value · Call by Reference · Object Passing

📦 Call by Value (Primitives)

Java passes a copy of the primitive value. Changes inside the method do NOT affect the original variable.

🔗 Call by Reference (Objects)

A copy of the reference (address) is passed. Changes to object's fields DO affect the original object. But reassigning the reference inside the method does not.

JavaPassing Primitives vs Objects
class Box {
    int value;
    Box(int v) { value = v; }
}

public class ArgPassing {
    // Primitive: copy passed — original unchanged
    static void changeInt(int x) { x = 999; }

    // Object: reference copy passed — fields CAN change
    static void changeBox(Box b) { b.value = 999; }

    // Comparing two objects via method
    static boolean isEqual(Box b1, Box b2) {
        return b1.value == b2.value;
    }

    public static void main(String[] args) {
        int n = 10;
        changeInt(n);
        System.out.println(n);            // 10 — unchanged!

        Box box = new Box(10);
        changeBox(box);
        System.out.println(box.value);    // 999 — changed!

        Box b1 = new Box(5), b2 = new Box(5);
        System.out.println(isEqual(b1, b2)); // true
    }
}

Returning Objects & Recursion

Methods returning Objects · Recursive Calls · Base Case

JavaReturning Object + Recursion (Factorial)
class Rectangle {
    int width, height;
    Rectangle(int w, int h) { width = w; height = h; }

    // Method returning an object (scaled version)
    Rectangle scale(int factor) {
        return new Rectangle(width * factor, height * factor);
    }
    void print() { System.out.println(width + " x " + height); }
}

public class RecursionDemo {
    // Recursion: factorial of n
    static int factorial(int n) {
        if (n == 0 || n == 1) return 1;  // BASE CASE — must have this!
        return n * factorial(n - 1);         // recursive call
    }

    static int fibonacci(int n) {
        if (n <= 1) return n;
        return fibonacci(n - 1) + fibonacci(n - 2);
    }

    public static void main(String[] args) {
        Rectangle r = new Rectangle(4, 3);
        Rectangle big = r.scale(3);
        big.print();                           // 12 x 9

        System.out.println(factorial(5));    // 120
        System.out.println(fibonacci(7));    // 13
    }
}
⚠️ Every recursive method MUST have a base case — without it, you get a StackOverflowError. The base case is what stops the infinite chain of calls.

final Keyword

final variable · final method · final class · Immutability

🔒 Three Uses of final

  • final variable — assigned only once (constant). If blank final: initialized in constructor.
  • final method — cannot be overridden by subclass
  • final class — cannot be subclassed (e.g., String, Integer)

❓ Exam Question

"What is the use of final keyword?"

Answer: All of the above (D) — when a class is final, no subclass can be created; when a method is final, it can't be overridden; when a variable is final, it can be assigned value only once.

Javafinal keyword usage
final class Constants {           // cannot be extended
    static final double PI = 3.14159; // constant — cannot change

    final void display() {            // cannot be overridden
        System.out.println("PI = " + PI);
    }
}

class Vehicle {
    final int maxSpeed;               // blank final — set in constructor
    Vehicle(int speed) { maxSpeed = speed; }
}

// class SubConstants extends Constants {} // ERROR: final class!

Inheritance Basics

IS-A · extends · Reusability · Types of Inheritance

🎬 Real World Scenario

A Vehicle class has speed, fuel, and move(). A Car IS-A Vehicle — it inherits all those. A ElectricCar IS-A Car — it inherits from Car. This chain is multilevel inheritance. We reuse code without rewriting it.

📐 Types of Inheritance in Java

TypeDescriptionSupported?
SingleA → B (one parent, one child)✅ Yes
MultilevelA → B → C (chain)✅ Yes
HierarchicalA → B and A → C (one parent, many children)✅ Yes
MultipleA + B → C (two parents — through classes)❌ Not via classes (use interface)
HybridMix of above⚠️ Via interface only
JavaSingle Inheritance Example
class Animal {
    String name;
    void eat() { System.out.println(name + " eats food"); }
    void breathe() { System.out.println(name + " breathes"); }
}

class Dog extends Animal {   // Dog IS-A Animal
    void bark() { System.out.println(name + " barks: Woof!"); }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.name = "Bruno";
        d.eat();     // inherited from Animal: Bruno eats food
        d.breathe(); // inherited: Bruno breathes
        d.bark();    // Dog's own: Bruno barks: Woof!
    }
}

Access Modifiers in Inheritance & super Keyword

Visibility in subclass · super.field · super() constructor

🔑 Access in Inheritance

  • public members — inherited and accessible everywhere
  • protected members — inherited; accessible in subclass even across packages
  • default members — only inherited within same package
  • private members — NOT inherited (but exist in object; accessible via public methods)
Javasuper keyword — 3 uses
class Parent {
    String color = "White";
    Parent() { System.out.println("Parent constructor"); }
    Parent(String msg) { System.out.println("Parent: " + msg); }
    void show() { System.out.println("Parent show"); }
}

class Child extends Parent {
    String color = "Blue";   // hides parent's color

    Child() {
        super("Hello from Child"); // USE 1: call parent constructor (MUST be first line)
    }

    void display() {
        System.out.println(super.color); // USE 2: parent field = White
        System.out.println(this.color);  // this field = Blue
        super.show();                     // USE 3: parent method
    }
}

public class Main {
    public static void main(String[] args) {
        Child c = new Child();  // Parent: Hello from Child
        c.display();            // White → Blue → Parent show
    }
}
💡 Key Rules for super(): Must be the very first statement in the child constructor. If you don't write super(), Java implicitly calls the no-arg parent constructor. If parent has no no-arg constructor, you MUST explicitly call super(args).

Multilevel Hierarchy

Chained Inheritance · Constructor Order · Method Resolution

JavaMultilevel Inheritance
class Vehicle {
    Vehicle() { System.out.println("Vehicle created"); }
    void move() { System.out.println("Vehicle moves"); }
}

class Car extends Vehicle {     // Car IS-A Vehicle
    Car() { System.out.println("Car created"); }
    void drive() { System.out.println("Car drives"); }
}

class ElectricCar extends Car { // ElectricCar IS-A Car IS-A Vehicle
    ElectricCar() { System.out.println("ElectricCar created"); }
    void charge() { System.out.println("Charging..."); }
}

public class Main {
    public static void main(String[] args) {
        ElectricCar ec = new ElectricCar();
        // Constructor order: Vehicle → Car → ElectricCar
        ec.move();    // inherited from Vehicle
        ec.drive();   // inherited from Car
        ec.charge();  // own method
    }
}
// Output:
// Vehicle created
// Car created
// ElectricCar created
// Vehicle moves
// Car drives
// Charging...
💡 Constructor Chain: In multilevel inheritance, constructors fire from the topmost parent down to child. This is because each child constructor implicitly (or explicitly) calls super() first.

📜 Rules for Overriding

  • Same method name as parent
  • Same parameter list as parent

Runtime Polymorphism

Dynamic Method Dispatch · Upcasting · Late Binding · JVM

🧠 The Core Idea

A parent class reference holds a child class object. When an overridden method is called on this reference, Java decides at runtime which version to call based on the actual object type, not the reference type.

This is also called Dynamic Method Dispatch or Late Binding.

JavaDynamic Method Dispatch — the classic example
class Animal {
    void sound() { System.out.println("Some animal sound"); }
}
class Dog extends Animal {
    @Override
    void sound() { System.out.println("Dog: Woof!"); }
}
class Cat extends Animal {
    @Override
    void sound() { System.out.println("Cat: Meow!"); }
}

public class RuntimePoly {
    public static void main(String[] args) {
        Animal a;   // parent reference

        a = new Dog();   // UPCASTING: Dog → Animal
        a.sound();       // Dog: Woof! (runtime decision)

        a = new Cat();   // same reference, different object
        a.sound();       // Cat: Meow! (runtime decision)

        a = new Animal();
        a.sound();       // Some animal sound

        // Polymorphic array — process different types uniformly
        Animal[] zoo = { new Dog(), new Cat(), new Dog() };
        for (Animal an : zoo) an.sound();
    }
}
⚠️ Can we override static methods? NO. Static methods belong to the class (not object), so they use method hiding, not overriding. The version called is determined by the reference type, not the object type. So base b = new derive(); b.show() calls base's static show — not derive's!

Abstract Classes

abstract keyword · Cannot Instantiate · Template Pattern · 0–100% Abstraction

📋 Key Points

  • Declared with abstract keyword
  • Cannot be instantiated (no new AbstractClass())
  • Can have both abstract methods (no body) and concrete methods (with body)
  • Can have constructors, static methods, and final methods
  • Subclass must implement all abstract methods (or be abstract itself)
  • Achieves 0 to 100% abstraction

🎬 Scenario — Payment Gateway

A Payment abstract class defines pay() as abstract — every payment method MUST implement it. But printReceipt() is concrete (same for all). CreditCard, UPI, and NetBanking all extend Payment and implement their own pay().

JavaAbstract Class — Shape Example
abstract class Shape {
    String color;

    // Abstract method — no body, MUST be implemented by subclass
    abstract double area();

    // Concrete method — same for all shapes
    void displayColor() {
        System.out.println("Color: " + color);
    }

    // Constructor (abstract class CAN have constructors)
    Shape(String c) { color = c; }
}

class Circle extends Shape {
    double radius;
    Circle(double r, String c) { super(c); radius = r; }

    @Override
    double area() { return 3.14 * radius * radius; }
}

class Triangle extends Shape {
    double base, height;
    Triangle(double b, double h, String c) { super(c); base=b; height=h; }

    @Override
    double area() { return 0.5 * base * height; }
}

public class Main {
    public static void main(String[] args) {
        // Shape s = new Shape("Red"); // ERROR: cannot instantiate abstract class

        Shape s1 = new Circle(5, "Red");      // upcasting
        Shape s2 = new Triangle(6, 4, "Blue");

        System.out.println(s1.area());   // 78.5
        s1.displayColor();               // Color: Red
        System.out.println(s2.area());   // 12.0
    }
}

Inheritance vs Composition

IS-A vs HAS-A · Design Decision · Code Reuse

🔗 Inheritance — IS-A

Use when child is a specialized type of parent.

  • Dog IS-A Animal ✅
  • Car IS-A Vehicle ✅
  • Square IS-A Shape ✅

Tight coupling — child depends on parent internals.

🧩 Composition — HAS-A

Use when one class contains another as a field.

  • Car HAS-A Engine ✅
  • Student HAS-A Address ✅
  • University HAS-A Department ✅

Loose coupling — easier to change components.

JavaComposition — HAS-A Relationship
class Engine {
    int horsepower;
    Engine(int hp) { horsepower = hp; }
    void start() { System.out.println("Engine starting... HP: " + horsepower); }
}

class Car {        // Car HAS-A Engine (not extends Engine)
    String model;
    Engine engine;   // composition: Engine object inside Car

    Car(String model, int hp) {
        this.model  = model;
        this.engine = new Engine(hp);  // Car creates its Engine
    }

    void drive() {
        engine.start();   // delegate to Engine
        System.out.println(model + " is driving");
    }
}

public class Main {
    public static void main(String[] args) {
        Car c = new Car("Swift", 90);
        c.drive();
        // Engine starting... HP: 90
        // Swift is driving
    }
}

🧭 When to Choose What?

SituationUse
Child truly IS a specialized version of parentInheritance
Child just USES services of another classComposition
Need to change implementation easily at runtimeComposition (more flexible)
Need polymorphism (method overriding)Inheritance
💡 Design principle: "Favor composition over inheritance" — but inheritance is not wrong. Use IS-A for polymorphism and HAS-A for code reuse of unrelated functionality. Getting this distinction right is a mark of a good OOP designer.
