L10-11
BST Insertion & Deletion
The core property, two-pointer insertion, three deletion cases

🔑 The ONE Rule That Everything Rests On

For every node N in a BST:

Left subtree values < N < Right subtree values
This applies to every node recursively, not just the root. The subtree rule is the most commonly missed point!

12 / \ 5 18 / \ / \ 2 9 15 19 / \ / \ 1 3 (no) 17 In-order: 1,2,3,5,9,12,15,17,18,19 → Always SORTED ✓

➕ BST Insertion — The Two-Pointer Walk

Key insight: A new key always becomes a leaf. Use two pointers — current (walks down) and parent (trails one step behind).

Example: Insert 13 into the tree above
Step 1: 13 > 12 → go RIGHT (current=18, parent=12)
Step 2: 13 < 18 → go LEFT (current=15, parent=18)
Step 3: 13 < 15 → go LEFT (current=NULL, parent=15)
→ Attach 13 as LEFT child of 15 ✓

Non-Recursive (Iterative) Insertion

struct Node* createNode(int data) {
    struct Node* node = (struct Node*)malloc(sizeof(struct Node));
    node->data = data;
    node->left = node->right = NULL;
    return node;
}

struct Node* insertIterative(struct Node* root, int key) {
    struct Node* newNode = createNode(key);
    if (root == NULL) return newNode;  // empty tree

    struct Node* current = root;
    struct Node* parent = NULL;

    while (current != NULL) {
        parent = current;                   // trail one step behind
        if (key < current->data)
            current = current->left;
        else
            current = current->right;
    }

    // parent is now where new node attaches
    if (key < parent->data)
        parent->left = newNode;
    else
        parent->right = newNode;

    return root;
}

Recursive Insertion

struct Node* insertRecursive(struct Node* root, int key) {
    if (root == NULL) return createNode(key);  // base case: empty slot
    
    if (key < root->data)
        root->left = insertRecursive(root->left, key);
    else if (key > root->data)
        root->right = insertRecursive(root->right, key);
    // if key == root->data, do nothing (no duplicates)
    
    return root;
}

❌ BST Deletion — Three Cases

Case 1: Leaf Node (0 children)

Simply detach the node. Set parent's pointer to NULL.

Case 2: One Child

The child takes the deleted node's place. Bypass the node.

Case 3: Two Children

Find the in-order successor (smallest in right subtree), copy its value, then delete the successor.

// Find minimum node (used for in-order successor)
struct Node* findMin(struct Node* node) {
    while (node->left != NULL)
        node = node->left;
    return node;
}

struct Node* deleteNode(struct Node* root, int key) {
    if (root == NULL) return NULL;

    if (key < root->data)
        root->left  = deleteNode(root->left, key);
    else if (key > root->data)
        root->right = deleteNode(root->right, key);
    else {
        // Found the node to delete
        if (root->left == NULL) {  // Case 1 & 2 (no left child)
            struct Node* temp = root->right;
            free(root);
            return temp;
        } else if (root->right == NULL) {  // Case 2 (no right child)
            struct Node* temp = root->left;
            free(root);
            return temp;
        }
        // Case 3: Two children — find in-order successor
        struct Node* successor = findMin(root->right);
        root->data = successor->data;  // copy successor value
        root->right = deleteNode(root->right, successor->data);
    }
    return root;
}

Time Complexity: O(log n) balanced | O(n) skewed (sorted input)

L12-13
BST Traversal & Searching
Inorder, Preorder, Postorder + Recursive & Non-Recursive Search

🔄 The Three Traversals

Inorder: Left → Root → Right

Output is always sorted for a BST. Used for sorting.

Preorder: Root → Left → Right

Used to clone/serialize a tree. Root comes first.

Postorder: Left → Right → Root

Used to delete a tree safely. Children deleted before parent.

Example Tree: 5 / \ 3 7 / \ / \ 2 4 9 X Inorder: 2 → 3 → 4 → 5 → 7 → 9 (SORTED ✓) Preorder: 5 → 3 → 2 → 4 → 7 → 9 Postorder: 2 → 4 → 3 → 9 → 7 → 5

Recursive Traversals (C Code)

void inorder(struct Node* root) {
    if (root == NULL) return;
    inorder(root->left);     // L
    printf("%d ", root->data); // N
    inorder(root->right);    // R
}

void preorder(struct Node* root) {
    if (root == NULL) return;
    printf("%d ", root->data); // N
    preorder(root->left);    // L
    preorder(root->right);   // R
}

void postorder(struct Node* root) {
    if (root == NULL) return;
    postorder(root->left);   // L
    postorder(root->right);  // R
    printf("%d ", root->data); // N
}

Non-Recursive Inorder (Using Stack)

void inorderIterative(struct Node* root) {
    struct Node* stack[100];
    int top = -1;
    struct Node* curr = root;

    while (curr != NULL || top >= 0) {
        while (curr != NULL) {
            stack[++top] = curr;   // push
            curr = curr->left;     // go left
        }
        curr = stack[top--];       // pop
        printf("%d ", curr->data);  // visit
        curr = curr->right;        // go right
    }
}

🔍 Searching in BST

Recursive Search

struct Node* searchRecursive(struct Node* root, int key) {
    if (root == NULL || root->data == key) return root;
    
    if (key < root->data)
        return searchRecursive(root->left, key);
    else
        return searchRecursive(root->right, key);
} // O(h) time

Non-Recursive (Iterative) Search

struct Node* searchIterative(struct Node* root, int key) {
    struct Node* ptr = root;
    while (ptr != NULL) {
        if (key == ptr->data) return ptr;    // found!
        else if (key < ptr->data) ptr = ptr->left;
        else ptr = ptr->right;
    }
    return NULL;  // not found
}

Find Min and Max

// Minimum: keep going LEFT until NULL
struct Node* findMin(struct Node* root) {
    while (root->left != NULL) root = root->left;
    return root;  // leftmost node
}
// Maximum: keep going RIGHT until NULL
struct Node* findMax(struct Node* root) {
    while (root->right != NULL) root = root->right;
    return root;  // rightmost node
}
L14-15
AVL Trees — Self-Balancing BST
Invented by Adelson-Velsky & Landis (1962). Four rotations to maintain balance.

🤔 Why AVL Trees?

A plain BST becomes a linked list if you insert sorted data (e.g., 10→20→30→40→50), making every operation O(n). AVL trees guarantee O(log n) for all operations by keeping the tree height-balanced.

BST (sorted input = disaster!) AVL Tree (always balanced) 10 30 \ / \ 20 vs. 10 40 \ \ / \ 30 20 35 50 \ 40 \ 50 ← O(n) search! ← O(log n) search ✓

📐 Balance Factor (BF)

BF(node) = Height(Left Subtree) − Height(Right Subtree)
Valid values: -1, 0, +1 only. Any other value means the tree is unbalanced → rotation needed!

BF ValueMeaning
+1Left subtree is one level higher (Left-Heavy)
0Both subtrees equal height (Balanced)
-1Right subtree is one level higher (Right-Heavy)
+2 or more❌ Unbalanced — needs rotation

Example: Calculate BF

12 (BF=+1) / \ 8(+1) 18(+1) / / 5(0) 17(0) Height of leaf = 0, Height of NULL = -1 BF(18) = h(left:17) - h(right:NULL) = 0 - (-1) = +1 ✓

🔄 The Four AVL Rotations

LL Rotation (Single Right Rotation)

New node inserted in Left child's Left subtree. Tree becomes Left-Heavy (BF > +1).
Fix: Rotate Right at imbalanced node.

Before:        After (Right Rotate A):
    A(+2)           B
   /               / \
  B(+1)    →      C   A
 /
C
RR Rotation (Single Left Rotation)

New node inserted in Right child's Right subtree. Tree becomes Right-Heavy (BF < -1).
Fix: Rotate Left at imbalanced node.

Before:        After (Left Rotate A):
A(-2)              B
  \               / \
   B(-1)  →      A   C
     \
      C
LR Rotation (Double: Left then Right)

New node in Left child's Right subtree.
Fix: First Left-rotate B, then Right-rotate A.

Before:     Step1(LR on B): Step2(RR on A):
  A(+2)         A               C
 /             /               / \
B(-1)  →      C       →       B   A
  \          /
   C        B
RL Rotation (Double: Right then Left)

New node in Right child's Left subtree.
Fix: First Right-rotate B, then Left-rotate A.

Before:     Step1(RR on B): Step2(LL on A):
A(-2)           A               C
  \               \             / \
   B(+1)  →        C    →      A   B
  /                  \
 C                    B

Memory Trick: The name tells you WHERE the new node went.
LL = new node is in Left's Left → fix with single Right rotation
RR = new node is in Right's Right → fix with single Left rotation
LR = Left's Right → fix with Left rotation first, then Right
RL = Right's Left → fix with Right rotation first, then Left

L16-17
Red-Black Trees (Insertion Only)
⚠️ Deletion NOT in MTE — focus on properties and insertion cases

🔴⚫ Why Red-Black Trees?

AVL trees are strictly balanced → great for searching but expensive to maintain (many rotations). RB Trees are loosely balanced → fewer rotations on insert/delete, faster updates.

AVL Tree

BF must be -1, 0, +1 at every node. More rotations on update. Better search performance.

Red-Black Tree

Colour-based balance. At most 2 rotations per insert. Slightly taller but faster updates.

📜 The 5 Red-Black Tree Properties

  1. Every node is either RED or BLACK.
  2. The root is always BLACK.
  3. Every leaf (NIL sentinel) is BLACK.
  4. If a node is RED, both its children must be BLACK. (No two consecutive red nodes!)
  5. For any node, all paths to descendant leaves contain the same number of BLACK nodes. (Black-height property)

Black-Height (bh): Number of black nodes on any path from a node to a leaf (not counting the node itself). This must be equal on every path.

➕ RB Tree Insertion — The 4 Cases

When we insert, we always colour the new node RED first. Then we fix violations.

Key Rule: A RED node cannot have a RED parent. If this happens → fix using one of these cases.

Case 1: Uncle is RED (Recoloring)

Parent and Uncle are both RED.
→ Recolour: Parent = BLACK, Uncle = BLACK, Grandparent = RED.
→ Move the problem up to Grandparent.

Case 2: Uncle is BLACK + Triangle

New node and Parent form a triangle (zigzag).
→ Rotate Parent to straighten into a line (sets up Case 3).

Case 3: Uncle is BLACK + Line

New node, Parent, Grandparent form a straight line.
→ Rotate Grandparent away. Swap colours of Parent and Grandparent.

Case 4: Root is RED

After fixing, if root becomes RED.
→ Simply recolour root to BLACK. (Increases black-height by 1)

⚠️ Remember for MTE: RB Tree DELETION is NOT in scope. Focus only on the 5 properties + insertion cases. Time complexity for all operations: O(log n)

L18-19
B-Trees: Properties, Insertion & Deletion
Multi-way search tree for disk storage and databases

💾 Why B-Trees?

BST, AVL, RB trees store 1 key per node → many disk accesses for large datasets. B-Trees store many keys per node, making the tree very wide and short → drastically fewer disk reads.

Real World Example: A database with 1 billion records. BST height ≈ 30. B-Tree of order 1000 height ≈ 3. That's 27 fewer disk accesses per query!

📋 B-Tree of Order m — Rules

  • Every node has at most m children
  • Every node (except root) has at least ⌈m/2⌉ children
  • Root has at least 2 children (if not a leaf)
  • A node with k children has k-1 keys
  • All leaves appear at the same level
  • Keys within each node are sorted
B-Tree of Order 3 (max 2 keys, 3 children): [17] / \ [8] [25 | 48] / \ / | \ [1,2][12,14][20][30][52,60] Max keys per node = m-1 = 2 Min keys (non-root) = ⌈m/2⌉-1 = 1

➕ B-Tree Insertion

ALGORITHM: B-Tree Insert(key)
1. Start at root, find the appropriate leaf node
2. Insert key in sorted order within that node
3. IF node has ≤ (m-1) keys → DONE (no overflow)
4. IF node overflows (m keys):
    a. Find the MIDDLE key (position ⌈m/2⌉)
    b. SPLIT node into two halves
    c. PROMOTE middle key to parent
    d. If parent overflows → repeat from step 4
5. If ROOT splits → create new root (tree grows taller by 1)

Worked Example — Build B-Tree of Order 5
Inserting: 1, 12, 8, 2, 25, 6, 14, 28, 17...
Max keys = 4 (m-1). Min keys (non-root) = 2.
First 4 keys fit in root: [1|2|8|12]
Insert 25 → overflow → middle key = 8 → promote 8
Root becomes [8], Left child = [1|2], Right child = [12|25]
Insert 6 → goes to left child → [1|2|6]
Insert 14 → goes to right child → [12|14|25]
Insert 28 → right child = [12|14|25|28] (full but ok)
Insert 17 → right child would be [12|14|17|25|28] → overflow!
Middle = 17 → promote 17 → root becomes [8|17]

Split with One Middle Key (Odd overflow)

Overflow node: [10 | 20 | 30 | 40 | 50]
Middle key = 30 → promote to parent

           [30]
          /    \
    [10|20]    [40|50]

Split with Two Middle Keys (Even overflow)

Overflow node: [10 | 20 | 30 | 40]
Two middles: 20 and 30 — pick one (be consistent!)

Option A (promote 20):    Option B (promote 30):
    [20]                      [30]
   /    \                    /    \
 [10]  [30|40]          [10|20]  [40]

❌ B-Tree Deletion

Cases for B-Tree Deletion
Case 1: Key is in a LEAF node
 → Simply remove it. If node still has ≥ ⌈m/2⌉−1 keys → DONE.

Case 2: Key is in an INTERNAL node
 → Replace with in-order predecessor OR successor (from a leaf).
 → Then delete that predecessor/successor from the leaf.

Underflow after deletion:
 Option A — BORROW from a sibling (if sibling has extra keys).
 Option B — MERGE with a sibling + pull down parent key.

Time Complexity: O(log n) for all operations

L21-22
Heaps & Heap Sort
Complete binary tree stored as array, with the heap property

🌳 What is a Heap?

Max-Heap

Every node's value ≥ its children. Root = Maximum element.

16 / \ 14 10 / \ / \ 8 7 9 3 / \ 2 4 Array: [16,14,10,8,7,9,3,2,4]

Min-Heap

Every node's value ≤ its children. Root = Minimum element.

2 / \ 4 6 / \ / \ 8 10 12 14 Array: [2,4,6,8,10,12,14]

Key Property: A heap is ALWAYS a Complete Binary Tree (all levels full except possibly the last, filled left to right).
This makes array representation perfect: for index i (0-based):
Parent = (i-1)/2 | Left child = 2i+1 | Right child = 2i+2

⬆️ Heapify — The Core Operation

MAX-HEAPIFY: Given a node that violates the heap property, fix it by swapping down.

void maxHeapify(int arr[], int n, int i) {
    int largest = i;        // assume root is largest
    int left  = 2*i + 1;
    int right = 2*i + 2;

    if (left  < n && arr[left]  > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;

    if (largest != i) {
        // swap and continue fixing downward
        int temp = arr[i];
        arr[i] = arr[largest];
        arr[largest] = temp;
        maxHeapify(arr, n, largest);  // recurse
    }
}

Build Heap from Array — O(n)

void buildMaxHeap(int arr[], int n) {
    // Start from last non-leaf node (n/2 - 1) and go up
    for (int i = n/2 - 1; i >= 0; i--)
        maxHeapify(arr, n, i);
} // O(n) — not O(n log n) !

Exam Tip: BUILD-MAX-HEAP starts from index n/2-1 (last non-leaf) down to 0, calling heapify on each. This is O(n) due to the mathematical analysis of how many nodes exist at each level.

📈 Heap Sort Algorithm

HEAP-SORT(A)
Step 1: BUILD-MAX-HEAP(A)           → O(n)
Step 2: for i from n-1 downto 1:
    Swap A[0] (max) with A[i]      → place max at end
    Reduce heap size by 1
    MAX-HEAPIFY(A, 0, i)         → O(log n) per step
Total: O(n log n) 
void heapSort(int arr[], int n) {
    buildMaxHeap(arr, n);  // Step 1
    
    for (int i = n - 1; i > 0; i--) {
        // Move current root (max) to end
        int temp = arr[0];
        arr[0] = arr[i];
        arr[i] = temp;
        // Heapify the reduced heap
        maxHeapify(arr, i, 0);
    }
}

Introduction to Graphs
G = (V, E) — the most general data structure for relationships

📖 What is a Graph?

A graph G = (V, E) is an ordered pair where V = set of vertices (nodes) and E = set of edges (connections between pairs of vertices).

Tree vs Graph: A tree is a restricted graph (connected, acyclic, n nodes have n-1 edges, one unique path between any two nodes). A graph is more general — can have cycles, multiple paths, disconnected components.

📚 Key Graph Terms

TermDefinition
Vertex (Node)A point in the graph
EdgeA connection between two vertices
AdjacencyTwo vertices are adjacent if connected by an edge
WalkA sequence of vertices where consecutive pairs are connected
PathA walk where no vertex is repeated (no repeated nodes)
CircuitA closed walk (start = end) where no vertex repeats (except start/end)
DegreeNumber of edges incident to a vertex
In-degreeNumber of edges ENTERING a vertex (directed graph)
Out-degreeNumber of edges LEAVING a vertex (directed graph)

🗂️ Types of Graphs

Directed Graph (Digraph)

Edges have direction (a,b) ≠ (b,a). Example: web links, one-way roads.

Undirected Graph

Edges have no direction {a,b} = {b,a}. Example: social networks, roads.

Weighted Graph

Each edge has a numerical value (weight). Example: road distances, costs.

Complete Graph

Every vertex connects to every other vertex. Directed: n(n-1) edges. Undirected: n(n-1)/2 edges.

Connected Graph

There is a path between every pair of vertices. Opposite = Disconnected.

Cyclic / Acyclic

Cyclic: has at least one cycle. Acyclic: no cycles (DAG = Directed Acyclic Graph).

Multigraph

Multiple edges allowed between the same pair of vertices.

Pseudograph

Allows self-loops (edge from a vertex to itself) + multiple edges.

Graph Representation & Operations
Adjacency Matrix vs Adjacency List — the core trade-off

📋 Adjacency Matrix

A V×V matrix where matrix[i][j] = 1 if edge exists between i and j (or the edge weight for weighted graphs).

// Graph: A-B, A-C, B-D, C-D, D-E
int adjMatrix[5][5] = {
//  A  B  C  D  E
  { 0, 1, 1, 0, 0 },  // A
  { 1, 0, 0, 1, 0 },  // B
  { 1, 0, 0, 1, 0 },  // C
  { 0, 1, 1, 0, 1 },  // D
  { 0, 0, 0, 1, 0 }   // E
};
// Symmetric for undirected graphs
// Check edge A-D: adjMatrix[0][3] = 0 → No edge → O(1)!
✅ Pros

O(1) edge lookup. Simple to implement. Easy to check if edge exists.

❌ Cons

O(V²) space always — wasteful for sparse graphs (few edges). Vertex addition requires resizing entire matrix.

📝 Adjacency List

An array of linked lists. List[i] stores all vertices adjacent to vertex i.

// Same graph using linked list
struct AdjNode { int vertex; struct AdjNode* next; };
struct AdjNode* adjList[5];

// A: → B → C
// B: → A → D
// C: → A → D
// D: → B → C → E
// E: → D

void addEdge(struct AdjNode* adjList[], int src, int dest) {
    struct AdjNode* newNode = (struct AdjNode*)malloc(sizeof(struct AdjNode));
    newNode->vertex = dest;
    newNode->next = adjList[src];
    adjList[src] = newNode;
    // For undirected, also add reverse edge
}
✅ Pros

O(V+E) space — efficient for sparse graphs. Fast neighbor traversal (O(degree(v))).

❌ Cons

Edge lookup is O(degree(v)) — must scan the list. More complex to implement.

🔍 BFS and DFS Traversals

BFS — Breadth First Search (Uses Queue)

void BFS(int graph[][], int start, int V) {
    bool visited[V] = {false};
    int queue[V], front=0, rear=0;
    
    visited[start] = true;
    queue[rear++] = start;
    
    while (front < rear) {
        int node = queue[front++];
        printf("%d ", node);
        for (int i=0; i<V; i++) {
            if (graph[node][i] && !visited[i]) {
                visited[i] = true;
                queue[rear++] = i;
            }
        }
    }
}

DFS — Depth First Search (Recursive)

bool visited[100] = {false};

void DFS(int graph[][], int node, int V) {
    visited[node] = true;
    printf("%d ", node);
    
    for (int i=0; i<V; i++) {
        if (graph[node][i] && !visited[i]) {
            DFS(graph, i, V);
        }
    }
}

  • Worst case: sorted input → O(n)

AVL Tree

  • BF = Height(Left) - Height(Right)
  • Valid BF: {-1, 0, +1} only
  • 4 rotations: LL, RR, LR, RL
  • LL/RR = single rotation | LR/RL = double

Red-Black Tree

  • 5 properties (especially: no two red in a row)
  • New nodes always inserted as RED
  • Uncle RED → recolour | Uncle BLACK → rotate
  • Deletion NOT in MTE ✓

B-Tree

  • Order m: max m-1 keys, min ⌈m/2⌉-1 keys
  • Overflow → split + promote middle key
  • All leaves at same level
  • Root split → tree height increases

Heap Quick Facts: Complete binary tree | Array-based (parent=(i-1)/2) | Build in O(n) | Sort in O(n log n) | Root = max (max-heap) or min (min-heap)

Graph Quick Facts: V=vertices, E=edges | Matrix: O(1) lookup, O(V²) space | List: O(V+E) space, O(degree) lookup | BFS uses Queue | DFS uses Stack/Recursion
