Definitions, structural types, mathematical properties, insertion, all 4 traversals, searching, and deletion

🌳 What is a Binary Tree?

A Binary Tree is a hierarchical non-linear data structure in which each node has at most two children, referred to as the left child and the right child.

Recursive Definition: A binary tree is either empty (NULL), or consists of a distinguished node called the root together with two disjoint binary trees called the left subtree and the right subtree.

Essential Terminology

TermDefinition & Explanation
RootThe topmost node of the tree with no parent (e.g. node A).
Parent & ChildIf an edge connects node U to node V (downward), U is parent and V is child.
Leaf Node (External)A node with 0 children (both left and right pointers are NULL).
Internal NodeA non-leaf node having at least one non-NULL child.
SiblingsNodes that share the same immediate parent.
Depth of NodeLength of the unique path from the root down to that node (Root depth = 0).
Height of NodeNumber of edges on the longest downward path from that node to a leaf (Leaf height = 0).
Height of TreeThe height of the root node (i.e. length of longest path from root to any leaf).
Degree of NodeNumber of children a node has (for binary trees: 0, 1, or 2).
Degree of TreeMaximum degree among all nodes in the tree (always ≤ 2 for Binary Trees).

📐 Types of Binary Trees

1. Full / Strict Binary Tree

Every node has either 0 or 2 children. No node has exactly 1 child.

1 / \ 2 3 / \ 4 5 ← (All nodes have 0 or 2 children)
2. Complete Binary Tree

All levels are completely filled except possibly the last level, which is filled strictly from left to right.

1 / \ 2 3 / \ / 4 5 6 ← (Last level filled left-to-right)
3. Perfect Binary Tree

All internal nodes have 2 children, and all leaf nodes are at the exact same level.

1 / \ 2 3 / \ / \ 4 5 6 7 ← Total nodes = 2^(h+1) - 1
4. Degenerate / Skewed Tree

Every internal node has only one child. The tree behaves like a linked list with worst-case performance O(n).

1 \ 2 (Right-skewed) \ 3 → Search is O(n)

Balanced Binary Tree: A binary tree where the difference between height of left subtree and right subtree for every node is at most 1 (e.g. AVL Tree).

💻 Complete C Implementation of Binary Tree

A general Binary Tree has no ordering restrictions. Nodes are inserted in level-order (filling the first empty left or right child spot) using a queue.

1. Node Structure & Node Creation

#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

struct Node {
    int data;
    struct Node* left;
    struct Node* right;
};

// Allocate and initialize a new node
struct Node* createNode(int val) {
    struct Node* newNode = (struct Node*)malloc(sizeof(struct Node));
    newNode->data = val;
    newNode->left = NULL;
    newNode->right = NULL;
    return newNode;
}

2. Insertion in Binary Tree (Level-Order using Queue)

In a standard Binary Tree, we insert a new key at the first available slot in breadth-first order so the tree remains complete and compact.

struct Node* insertBT(struct Node* root, int val) {
    struct Node* newNode = createNode(val);
    if (root == NULL) return newNode;

    // Queue array for level-order traversal
    struct Node* queue[100];
    int front = 0, rear = 0;

    queue[rear++] = root;

    while (front < rear) {
        struct Node* temp = queue[front++];

        // Check left child
        if (temp->left == NULL) {
            temp->left = newNode;
            return root;
        } else {
            queue[rear++] = temp->left;
        }

        // Check right child
        if (temp->right == NULL) {
            temp->right = newNode;
            return root;
        } else {
            queue[rear++] = temp->right;
        }
    }
    return root;
}

3. All Four Traversals (Preorder, Inorder, Postorder, Level-Order)

// 1. Inorder Traversal: Left -> Root -> Right
void inorder(struct Node* root) {
    if (root == NULL) return;
    inorder(root->left);
    printf("%d ", root->data);
    inorder(root->right);
}

// 2. Preorder Traversal: Root -> Left -> Right
void preorder(struct Node* root) {
    if (root == NULL) return;
    printf("%d ", root->data);
    preorder(root->left);
    preorder(root->right);
}

// 3. Postorder Traversal: Left -> Right -> Root
void postorder(struct Node* root) {
    if (root == NULL) return;
    postorder(root->left);
    postorder(root->right);
    printf("%d ", root->data);
}

// 4. Level-Order Traversal (Breadth-First using Queue)
void levelOrder(struct Node* root) {
    if (root == NULL) return;
    struct Node* queue[100];
    int front = 0, rear = 0;
    queue[rear++] = root;

    while (front < rear) {
        struct Node* curr = queue[front++];
        printf("%d ", curr->data);
        if (curr->left != NULL)  queue[rear++] = curr->left;
        if (curr->right != NULL) queue[rear++] = curr->right;
    }
}

4. Searching in a Binary Tree

Unlike BSTs, keys are not sorted. In the worst case we must inspect every node: time complexity is O(n).

// Recursive search in general binary tree
bool searchBT(struct Node* root, int target) {
    if (root == NULL) return false;
    if (root->data == target) return true;
    return searchBT(root->left, target) || searchBT(root->right, target);
}

5. Deletion in a Binary Tree (Deepest Node Replacement Strategy)

In a General Binary Tree (not BST), deleting a node without shrinking height arbitrarily is done by:
1. Finding the target node to delete.
2. Finding the deepest and rightmost node in the tree using level-order traversal.
3. Copying the deepest node's data into the target node.
4. Unlinking and freeing the deepest node.

// Helper: Deletes the deepest rightmost node from the tree
void deleteDeepest(struct Node* root, struct Node* dNode) {
    struct Node* queue[100];
    int front = 0, rear = 0;
    queue[rear++] = root;

    while (front < rear) {
        struct Node* curr = queue[front++];

        if (curr == dNode) {
            free(dNode);
            return;
        }
        if (curr->right != NULL) {
            if (curr->right == dNode) {
                curr->right = NULL;
                free(dNode);
                return;
            } else {
                queue[rear++] = curr->right;
            }
        }
        if (curr->left != NULL) {
            if (curr->left == dNode) {
                curr->left = NULL;
                free(dNode);
                return;
            } else {
                queue[rear++] = curr->left;
            }
        }
    }
}

// Main BT Deletion Function
struct Node* deleteBTNode(struct Node* root, int key) {
    if (root == NULL) return NULL;

    // If only 1 node in tree
    if (root->left == NULL && root->right == NULL) {
        if (root->data == key) { free(root); return NULL; }
        return root;
    }

    struct Node* queue[100];
    int front = 0, rear = 0;
    queue[rear++] = root;

    struct Node* targetNode = NULL;
    struct Node* temp = NULL;

    // Level order traversal to find target and the deepest node
    while (front < rear) {
        temp = queue[front++];

        if (temp->data == key)
            targetNode = temp;

        if (temp->left != NULL)  queue[rear++] = temp->left;
        if (temp->right != NULL) queue[rear++] = temp->right;
    }

    // If target was found, swap data with deepest node and delete deepest
    if (targetNode != NULL) {
        int deepestValue = temp->data; // temp holds deepest rightmost node
        deleteDeepest(root, temp);
        targetNode->data = deepestValue;
    }
    return root;
}

BST Insertion & Deletion
The core property, two-pointer insertion, three deletion cases, and detailed traces

🔑 The ONE Rule That Everything Rests On

For every node N in a BST:

Left subtree values < N < Right subtree values
This applies to every node recursively, not just the root. The subtree rule is the most commonly missed point!

12 / \ 5 18 / \ / \ 2 9 15 19 / \ / \ 1 3 (no) 17 In-order: 1, 2, 3, 5, 9, 12, 15, 17, 18, 19 → Always SORTED ✓

➕ BST Insertion — The Two-Pointer Walk

Key insight: A new key always becomes a leaf. Use two pointers — current (walks down) and parent (trails one step behind).

Non-Recursive (Iterative) Insertion

struct Node* insertIterative(struct Node* root, int key) {
    struct Node* newNode = createNode(key);
    if (root == NULL) return newNode;

    struct Node* current = root;
    struct Node* parent = NULL;

    while (current != NULL) {
        parent = current;
        if (key < current->data)
            current = current->left;
        else if (key > current->data)
            current = current->right;
        else {
            free(newNode); // duplicate key, ignore
            return root;
        }
    }

    if (key < parent->data)
        parent->left = newNode;
    else
        parent->right = newNode;

    return root;
}

Recursive Insertion

struct Node* insertRecursive(struct Node* root, int key) {
    if (root == NULL) return createNode(key);
    
    if (key < root->data)
        root->left = insertRecursive(root->left, key);
    else if (key > root->data)
        root->right = insertRecursive(root->right, key);
    
    return root;
}

❌ BST Deletion — Three Distinct Cases

Case 1: Leaf Node (0 children)

Simply detach the node and free memory. Set the parent's pointer to NULL.

Case 2: Node with One Child

The single child takes the deleted node's place. Bypass the node and link parent directly to grandchild.

Case 3: Node with Two Children

Find the in-order successor (smallest in right subtree), copy its value into current node, then delete the successor.

struct Node* findMin(struct Node* node) {
    while (node->left != NULL)
        node = node->left;
    return node;
}

struct Node* deleteNode(struct Node* root, int key) {
    if (root == NULL) return NULL;

    if (key < root->data)
        root->left  = deleteNode(root->left, key);
    else if (key > root->data)
        root->right = deleteNode(root->right, key);
    else {
        // Case 1 & 2: 0 or 1 child
        if (root->left == NULL) {
            struct Node* temp = root->right;
            free(root);
            return temp;
        } else if (root->right == NULL) {
            struct Node* temp = root->left;
            free(root);
            return temp;
        }
        // Case 3: Two children
        struct Node* successor = findMin(root->right);
        root->data = successor->data;
        root->right = deleteNode(root->right, successor->data);
    }
    return root;
}

🔄 The Three Depth Traversals

Inorder: Left → Root → Right

Output is strictly sorted for a BST. Used to produce sorted records in $O(n)$ time.

Preorder: Root → Left → Right

Used to clone or serialize a tree structure. Root is always processed first.

Postorder: Left → Right → Root

Used to delete or free a tree from bottom to top, or evaluate prefix/postfix expressions.

Non-Recursive (Iterative) Inorder Traversal using Explicit Stack

void inorderIterative(struct Node* root) {
    struct Node* stack[100];
    int top = -1;
    struct Node* curr = root;

    while (curr != NULL || top >= 0) {
        // Step 1: Reach the leftmost node of current subtree
        while (curr != NULL) {
            stack[++top] = curr;
            curr = curr->left;
        }
        // Step 2: Pop and visit
        curr = stack[top--];
        printf("%d ", curr->data);

        // Step 3: Now traverse right subtree
        curr = curr->right;
    }
}

🔍 Searching in BST

Recursive Search

struct Node* searchRec(struct Node* root, int key) {
    if (root == NULL || root->data == key)
        return root;
    if (key < root->data)
        return searchRec(root->left, key);
    return searchRec(root->right, key);
}

Iterative Search (O(1) Space)

struct Node* searchIter(struct Node* root, int key) {
    struct Node* curr = root;
    while (curr != NULL) {
        if (key == curr->data) return curr;
        else if (key < curr->data) curr = curr->left;
        else curr = curr->right;
    }
    return NULL;
}

AVL Trees — Self-Balancing BST
Balance factors, 4 rotations, step-by-step construction, and rebalancing traces

🤔 Why AVL Trees?

A plain BST becomes a degenerate linked list if you insert sorted data (e.g., 10→20→30→40→50), degrading search to O(n). AVL trees strictly guarantee O(log n) for all operations by maintaining a height-balance property at every node.

📐 Balance Factor (BF)

BF(node) = Height(Left Subtree) − Height(Right Subtree)
Valid values: -1, 0, +1 only. Any other value (|BF| ≥ 2) means the tree is unbalanced → rotation required!

BF ValueMeaningAction Required
+1Left subtree is 1 level taller than right subtree (Left-Heavy)Balanced ✓
0Both subtrees are of equal heightBalanced ✓
-1Right subtree is 1 level taller than left subtree (Right-Heavy)Balanced ✓
+2 or -2Critical imbalance along the insertion pathRotate Immediately ⚠

L16-17
Red-Black Trees (Insertion Only)
⚠️ Deletion NOT in MTE — 5 properties, black-height, and 4 insertion cases

📜 The 5 Red-Black Tree Properties

  1. Every node is either RED or BLACK.
  2. The root is always BLACK.
  3. Every leaf (NIL sentinel) is BLACK.
  4. If a node is RED, both its children must be BLACK. (No two consecutive RED nodes!)
  5. For every node, all paths from that node to descendant leaves contain the EXACT SAME number of black nodes (Black-Height property).

➕ RB Tree Insertion Rules (New Node is Always RED)

When inserting a new key, we always colour it RED first to avoid violating Property 5 (black-height). If its parent is BLACK, we are done. If its parent is RED, we fix the double-red violation using 4 cases based on the uncle's colour.

Case 1: Uncle is RED (Recoloring)

Parent = BLACK, Uncle = BLACK, Grandparent = RED.
Move pointer to Grandparent and repeat check upward.

Case 2: Uncle is BLACK (Triangle / Zig-zag)

Rotate Parent opposite to new node to convert triangle into a straight line (transforms into Case 3).

Case 3: Uncle is BLACK (Line)

Rotate Grandparent away from new node. Swap colors of Parent (now BLACK) and Grandparent (now RED).

Case 4: Root is RED

If root became RED due to Case 1 propagation, simply recolour root to BLACK. Increases black-height by 1.

B-Trees: Properties, Insertion & Deletion
Multi-way search tree optimized for disk storage and database indexing

📋 B-Tree of Order m — The Golden Rules

Rule PropertyRoot NodeInternal / Non-Root Node
Max Children$m$$m$
Min Children$2$ (if not a leaf)$\lceil m/2 \rceil$
Max Keys$m - 1$$m - 1$
Min Keys$1$$\lceil m/2 \rceil - 1$
Leaf LevelAll leaf nodes must appear at the exact same depth/level.

➕ B-Tree Insertion & Splitting

Keys are always inserted into leaf nodes. When a node overflows (reaches $m$ keys):
1. Identify the median key at index $\lceil m/2 \rceil$.
2. Split the node into left child and right child.
3. Promote the median key to the parent node.
4. If the root splits, a new root is created (this is the only way a B-tree grows in height).

On tree with Root [20 | 40] and children [10], [30], [50]:

Scenario A (Underflow Borrowing): If a node underflows and an immediate sibling has extra keys, borrow via parent rotation.

Scenario B (Underflow Merging): If siblings have minimum keys, delete key, pull down the divider key from parent, and merge sibling nodes into one single node. If root empties, the merged node becomes the new root.

💼 Real-World Architectural Case Studies

Case 1: Linux Kernel Completely Fair Scheduler (CFS)

Choice: Red-Black Tree
Tasks are indexed by execution time. Frequent insertions/deletions as processes wake and sleep. RB Trees require fewer rebalancing rotations ($O(1)$ amortized) than AVL trees, giving lower OS latency.

Case 2: PostgreSQL / MySQL Database Indexes

Choice: B-Tree / B+Tree
Disk block reads are 100,000x slower than RAM. High fan-out ($m \ge 500$) keeps tree height $\le 3$, answering queries over millions of rows with at most 3 disk I/Os.

Case 3: In-Memory Static Dictionary / Read-Heavy Cache

Choice: AVL Tree
Once loaded, data is queried millions of times without modifications. AVL's stricter balance factor guarantees shorter average search path than Red-Black trees.

Case 4: Compiler Symbol Table (Small Scopes)

Choice: Binary Search Tree (or Hash Table)
In short local scopes (e.g., function arguments), $N$ is small ($\le 20$). The overhead of maintaining balance factors or node colors outweighs the cost of simple BST pointer walks.

Heaps & Heap Sort
Complete binary trees in arrays, Max-Heapify, Build-Heap, and sorting traces

🌳 What is a Heap?

A Binary Heap is a Complete Binary Tree stored consecutively in an array that satisfies the Heap Property:

Max-Heap Property

For every node $i$: A[parent(i)] ≥ A[i]. Root holds the MAXIMUM element.

Min-Heap Property

For every node $i$: A[parent(i)] ≤ A[i]. Root holds the MINIMUM element.

Array Indexing Rules (0-based indexing):
For node at index $i$:
• Parent: (i - 1) / 2
• Left Child: 2 * i + 1
• Right Child: 2 * i + 2
• Last Non-Leaf Node: n / 2 - 1

⚙️ Heapify & Heap Sort Implementation

// Max-Heapify: Swaps downward until heap property is restored
void maxHeapify(int arr[], int n, int i) {
    int largest = i;
    int left  = 2 * i + 1;
    int right = 2 * i + 2;

    if (left < n && arr[left] > arr[largest])
        largest = left;
    if (right < n && arr[right] > arr[largest])
        largest = right;

    if (largest != i) {
        int temp = arr[i];
        arr[i] = arr[largest];
        arr[largest] = temp;
        maxHeapify(arr, n, largest); // Recurse down
    }
}

// Build-Max-Heap: O(n) total time
void buildMaxHeap(int arr[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--)
        maxHeapify(arr, n, i);
}

// Heap-Sort: O(n log n) in-place sorting
void heapSort(int arr[], int n) {
    buildMaxHeap(arr, n);

    for (int i = n - 1; i > 0; i--) {
        // Move current max (root) to end of array
        int temp = arr[0];
        arr[0] = arr[i];
        arr[i] = temp;

        // Re-heapify root with reduced heap size i
        maxHeapify(arr, i, 0);
    }
}

Introduction to Graphs
Graph formalisms, terminology, Handshaking Lemma, and classification

📖 Formal Definition

A Graph $G = (V, E)$ consists of a non-empty set of vertices $V$ and a set of edges $E$ that connect pairs of vertices.

Tree vs Graph: A Tree is a strictly connected, acyclic graph with exactly $N - 1$ edges. A General Graph may contain cycles, disconnected components, self-loops, or multiple edges.

🤝 The Handshaking Lemma

Fundamental Theorem: For any undirected graph $G = (V, E)$:
$$\sum_{v \in V} \text{deg}(v) = 2 \cdot |E|$$ Direct Consequence: The number of vertices with an odd degree is always EVEN.

Graph Representation & Memory Models
Adjacency Matrix vs Adjacency List — implementation, space/time complexity, and trade-offs

📋 Adjacency Matrix

A 2D array of size $V \times V$ where matrix[i][j] = 1 (or weight $W$) if an edge exists from $i$ to $j$, and 0 otherwise.

// Adjacency Matrix Definition and Edge Addition
#define V 5
int adjMatrix[V][V] = {0};

void addEdgeMatrix(int u, int v, bool directed) {
    adjMatrix[u][v] = 1;
    if (!directed) {
        adjMatrix[v][u] = 1;
    }
}

📝 Adjacency List

An array of linked lists of size $V$. Each entry adjList[i] stores a linked list of all vertices adjacent to vertex $i$.

struct AdjNode {
    int dest;
    int weight;
    struct AdjNode* next;
};

struct AdjNode* adjList[V] = {NULL};

void addEdgeList(int src, int dest, int weight, bool directed) {
    struct AdjNode* newNode = (struct AdjNode*)malloc(sizeof(struct AdjNode));
    newNode->dest = dest;
    newNode->weight = weight;
    newNode->next = adjList[src];
    adjList[src] = newNode;

    if (!directed) {
        struct AdjNode* revNode = (struct AdjNode*)malloc(sizeof(struct AdjNode));
        revNode->dest = src;
        revNode->weight = weight;
        revNode->next = adjList[dest];
        adjList[dest] = revNode;
    }
}

🧠 Must-Remember Exam Facts

Binary Tree & BST

  • General BT: Unordered; search & deletion are $O(n)$.
  • BT Deletion: Swap with deepest rightmost node.
  • Max nodes in height $h$: $2^{h+1} - 1$.
  • BST: Left < Root < Right. In-order = sorted.
  • BST Deletion Case 3: Replace with in-order successor.

AVL Tree

  • BF = Height(Left) − Height(Right) $\in \{-1, 0, +1\}$.
  • LL / RR: Single rotation at unbalanced node.
  • LR / RL: Double rotation (child first, then node).

Red-Black & B-Tree

  • RB Tree: 5 properties; no two red nodes consecutively.
  • New nodes inserted RED; uncle RED $\to$ recolor.
  • Deletion NOT in scope for Red-Black Tree.
  • B-Tree: Multi-way search tree; all leaves at same depth.
  • Overflow $\to$ Split node & promote median key.

Heaps & Graphs

  • Heap: Complete binary tree in array (parent = $(i-1)/2$).
  • Build-Max-Heap: $O(n)$ time | Heap Sort: $O(n \log n)$.
  • Handshaking Lemma: $\sum \text{deg}(v) = 2|E|$.
  • Dense graph $\to$ Matrix | Sparse graph $\to$ List.
