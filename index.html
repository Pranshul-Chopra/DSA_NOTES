01

Constructors

HIGH

What is a Constructor?

A special method called automatically when an object is created (new keyword). Initializes the object. Same name as class, no return type at all — not even void.

Rules (memorize these — they appear as MCQs)

✗ Cannot be static, abstract, or final
✗ Cannot be inherited by subclasses
✗ No return type (adding void makes it a regular method, not constructor!)
✓ Can be overloaded
✓ Can call another constructor using this()
✓ Abstract class can have a constructor

3 Types of Constructors

// All three types in one class
class Student {
    int id;
    String name;

    // 1. Default (no args)
    Student() {
        id = 0; name = "Unknown";
    }

    // 2. Parameterized
    Student(int id, String name) {
        this.id = id;
        this.name = name;
    }

    // 3. Copy constructor
    Student(Student s) {
        this.id = s.id;
        this.name = s.name;
    }
}

Constructor Chaining (using this())

Calling one constructor from another within the same class. this() must be the first statement.

// this() chains constructors
class Box {
    Box() {
        this(10); // calls Box(int)
        System.out.println("default");
    }
    Box(int size) {
        System.out.println("size: " + size);
    }
}
// new Box() → prints: size: 10 → then: default

Execution Order: Static Block → Instance Block → Constructor

// Order of execution
class Demo {
    static { System.out.println("1 static block"); }
    { System.out.println("2 instance block"); }
    Demo() { System.out.println("3 constructor"); }
}
// Output: 1 → 2 → 3
// Static block runs only ONCE (at class load)
// Instance block runs before EVERY constructor call
⚠ Tricky PYQ pattern: If you write void Demo() inside a class called Demo, that is a method not a constructor (because of the void). The real constructor Demo() still gets auto-generated by the compiler. Both exist and both can be called — but only one is the constructor.
Output question trick: When new Box() calls this(10), control jumps to Box(int) first and finishes it, THEN comes back and prints the rest of Box(). Trace this carefully.
02

this keyword

HIGH

What is this?

A reference variable that refers to the current object. It has 6 uses.

6 Uses of this

  • 1. Refer to current class instance variable — disambiguate when param name = field name
  • 2. Invoke current class method — this.display() (usually implicit)
  • 3. this() — invoke current class constructor — must be first line
  • 4. Pass as argument in method call — someMethod(this)
  • 5. Pass as argument in constructor call — new Other(this)
  • 6. Return current instance — return this;

Most Common Use: Disambiguating field vs parameter

// Without this — parameter hides field
class Student {
    int rollno;
    Student(int rollno) {
        this.rollno = rollno; // this.rollno = field
        // rollno = rollno (right side) = parameter
    }
}

// PYQ trap: what if this.rollno is NOT used?
// then field stays 0 (default), parameter is ignored!

Output Prediction from PYQ slides

// What does this print?
class Main {
    int a = 500, b = 300;
    void sum(int a, int b) {
        System.out.println(this.a + this.b);
    }
    public static void main(String[] args) {
        new Main().sum(45, 60);
    }
}
// Answer: 800 (this.a=500, this.b=300, ignores params)
03

Inheritance & super keyword

HIGH

What is Inheritance?

One class acquires properties and methods of another. Represents IS-A relationship. Uses extends keyword. Java supports single, multilevel, hierarchical inheritance with classes. Multiple inheritance through classes is NOT allowed — only through interfaces.

Types of Inheritance in Java

  • Single — A → B
  • Multilevel — A → B → C (chain)
  • Hierarchical — A → B, A → C, A → D
  • Multiple — ❌ not allowed with classes, ✓ allowed via interfaces
  • Hybrid — combination (via interfaces only)

super keyword — 3 uses

1 Refer to parent class instance variable — super.name
2 Invoke parent class method — super.display()
3 Invoke parent class constructor — super() or super(args) — must be first line

Constructor Chaining Across Classes (KEY for Section C)

// PYQ pattern — B extends A
class A {
    A() { System.out.println("Inside A constructor"); }
}
class B extends A {
    B() { System.out.println("Inside B constructor"); }
}
class Main {
    public static void main(String[] args) {
        new B();
    }
}
// Output:
// Inside A constructor   ← parent always runs first
// Inside B constructor
Why? Java secretly inserts super() as the first line of every constructor if you don't explicitly call super or this. So B's constructor always calls A's first.

Access Modifiers in Inheritance

ModifierSame classSubclass (same pkg)Subclass (diff pkg)Outside
public✓✓✓✓

What is NOT inherited?

  • Constructors — but you can call them via super()
  • Private members — but accessible via public/protected getters

Abstract Class & final keyword

HIGH

Abstract Class — Key Points

✓ Declared with abstract keyword
✓ Can have both abstract methods (no body) and non-abstract methods (with body)
✓ Can have constructors, static methods, final methods
✗ Cannot be instantiated (cannot do new AbstractClass())
✗ If a subclass doesn't implement all abstract methods, it must also be abstract

Abstract Class Example (Section C pattern)

// Abstract parent → Concrete child
abstract class Shape {
    abstract void draw();          // no body
    void describe() {              // has body
        System.out.println("I am a shape");
    }
}
class Circle extends Shape {
    void draw() {                  // must implement
        System.out.println("Drawing circle");
    }
}
// Shape s = new Shape(); ← ERROR
// Shape s = new Circle(); ← OK (upcasting)

final keyword — 3 uses

Applied toEffect
final variableValue cannot be changed (constant)
final methodCannot be overridden in subclass
final classCannot be extended (subclassed)
PYQ trap: If displayInfo() is declared final in parent class, the child class cannot override it — this gives a compile-time error. This was directly asked in your Section C question.

Runtime Polymorphism

HIGH

Compile-time vs Runtime — Quick comparison

Compile-time (Static)Runtime (Dynamic)
Also calledEarly binding, OverloadingLate binding, Overriding
ResolvedAt compile timeAt runtime by JVM
Inheritance?Not requiredRequired
SpeedFasterSlower

Method Overriding Rules

✓ Same method name as parent
✓ Same parameters as parent
✓ IS-A relationship must exist (inheritance)
✗ Cannot override static methods (static binding)
✗ Cannot override final methods
✗ Overriding method cannot be MORE restrictive (e.g. can't make public → protected)

Upcasting + Dynamic Dispatch (the core mechanism)

// Upcasting: parent reference → child object
class Bank {
    float getRateOfInterest() { return 0; }
}
class SBI extends Bank {
    float getRateOfInterest() { return 8.4f; }
}
class ICICI extends Bank {
    float getRateOfInterest() { return 7.3f; }
}

Bank b = new SBI();   // upcasting
b.getRateOfInterest(); // returns 8.4 (SBI's version)

b = new ICICI();
b.getRateOfInterest(); // returns 7.3 (ICICI's version)
// JVM decides at runtime based on the actual object
Key rule: The reference type (Bank) determines what methods you CAN call. The actual object type (SBI) determines WHICH version of the method runs.

Static method "overriding" — method hiding, not overriding

// Static methods use static binding
class Base  { static void show() { print("base"); } }
class Derive extends Base { static void show() { print("derive"); } }

Base b = new Derive();
b.show(); // prints "base" ← reference type wins, not object!
// This is method HIDING not overriding
⚠ PYQ appeared: base b = new derive(); b.displayderive(); — this gives a compile error because displayderive() is only in the derive class, not in the base reference type. The reference type limits what you can call.

Method Overloading

HIGH

What is Overloading?

Multiple methods with the same name but different parameters (number, type, or order of parameters). Resolved at compile time — compile-time polymorphism.

Ways to Overload

// 3 overloaded add() methods
int add(int a, int b)            // 2 ints
double add(double a, double b)  // 2 doubles (different types)
int add(int a, int b, int c)   // 3 ints (different count)

// NOT valid overloading — return type alone is not enough:
// int add(int a, int b)
// double add(int a, int b)  ← same params = compile error

Overloading vs Overriding — The Big Table

OverloadingOverriding

Same params✗ (different)✓ (must be same)
InheritanceNot neededRequired

Return typeCan differMust be same (or covariant)

static keyword

MEDIUM

static variable

Shared across all objects of the class. Memory allocated once at class load time. Use for common properties (e.g. college name of all students).

// Instance vs Static variable
class Student {
    int id;                    // unique per object
    static String college;    // shared by all objects
}
// s1.college = s2.college — both see same value

static method

✓ Can access static data directly
✓ Called via class name: ClassName.method()
✗ Cannot access instance variables directly
✗ Cannot use this or super
✗ Cannot be overridden (only hidden)

Execution order with static block

Static block → static method (if called) → instance block → constructor. Static block runs once when class is loaded.

// Common output question
class A {
    static { print("static block"); }  // runs first, once
    { print("instance block"); }        // runs per object
    A() { print("constructor"); }
}
// new A(); new A();
// Output: static block → instance block → constructor
//                      → instance block → constructor

Access Modifiers

MEDIUM

Visibility at a glance

From most restrictive to least: private → default → protected → public

Overriding rule: When overriding, you can only make the method less restrictive (more visible), never more restrictive. protected can become public. public cannot become protected.

PYQ pattern — private access from outside

// This was Q A1(a) in your PYQ
class Example {
    int a;
    private int c;
}
class Demo {
    public static void main(String[] args) {
        Example ob = new Example();
        ob.a = 10;   // ✓ OK
        ob.c = 20;   // ✗ COMPILE ERROR — private!
    }
}
